工程架构


文档职责：

    只记录稳定运行形态、源码边界、数据流、存储边界和关键命名规则。
    不记录产品愿景、详细需求、样式细节、个人环境、当前任务和近期排期。


1. 运行形态

当前运行形态：

    Browser React UI
    Node HTTP API
    Local File Store

当前不维护 Tauri 桌面运行层。

Docker 只属于 HTTP 后端的部署形态，不改变前端、API 和文件仓库边界。


2. 总体分层

    Browser React UI
        -> Workspace 应用层
        -> Domain Layer
        -> CTN + Syntax Core
        -> Storage Port
        -> HTTP Adapter
        -> Node HTTP API
        -> File Store

分层职责：

    UI 负责交互、布局和视图状态。
    Workspace 应用层负责 session、command 编排、view model 和 workflow。
    Domain 负责可测试的纯规则。
    CTN Core 只解析 .ctn 原文。
    Syntax Core 负责语法 profile、TOML 解析、校验和序列化。
    Storage Port 由 WorkspaceRepository 表示。
    Node HTTP API 和 File Store 负责安全读写本地文件仓库。

基本原则：

    数据正确性规则不放在 React 组件中。
    CTN parser 必须显式接收 CtnSyntaxProfile。
    src/syntax 是前端语法 profile 的权威来源。
    server/syntaxProfileToml.mjs 当前保留独立 Node 实现，由 parity tests 固定一致性。


3. 源码目录

    src/app/          React 应用组合
    src/features/     功能界面：notes、syntax、migration、visualization
    src/shell/        应用外壳、活动栏、侧栏
    src/workspace/    前端应用层、session、commands、view model、workflow
    src/domain/       notes、noteTree、noteBlockText、noteBlockMigration、workspaceActions
    src/ctn/          CTN 原文解析
    src/syntax/       语法 profile、TOML、默认语法
    src/editor/       CodeMirror 集成
    src/storage/      WorkspaceRepository 端口和适配器
    src/styles/       全局样式；细节见 docs/界面样式约定.txt
    server/           Node HTTP API 和文件仓库
    tests/            按模块边界组织的测试


4. 关键边界

UI / Workspace / Domain：

    UI 只展示和触发命令。
    Workspace 串联 repository、当前选择、语法状态和跨模块 workflow。
    Domain 只处理普通对象输入输出的纯规则。

CTN / Syntax / Workspace：

    src/syntax 解析 syntax/workspace.toml，输出 CtnSyntaxProfile。
    src/ctn 解析 note.source，输入必须包含 CtnSyntaxProfile。
    src/workspace 解析 workspace 中的语法状态，输出 view model 或 workflow 结果。

Storage：

    前端只依赖 WorkspaceRepository。
    HTTP WorkspaceRepository 是标准实现。
    browser localStorage 仅作为显式开发备选。
    后端保存前校验 workspace payload 和语法文件。
    文件写入必须串行，并用临时文件 + rename 原子替换权威文件。


5. 文件仓库模型

权威源文件：

    workspace.json
    notes/*.ctn
    syntax/workspace.toml

边界：

    workspace.json 保存 workspace 元信息、activeNoteId、notes 元信息和目录树。
    notes/*.ctn 保存每篇笔记原文。
    syntax/workspace.toml 保存仓库唯一语法配置。
    workspace.json 不保存语法 profile 权威内容。
    NoteWorkspace 是前端运行时聚合，包含 WorkspaceData 和解析后的 syntaxProfile。
    WorkspaceRepository 读写 workspace 时只传输 WorkspaceData。

后续索引：

    index.sqlite 可作为派生缓存。
    FTS5 可用于全文搜索。
    索引缓存不替代权威源文件。
    第一版笔记级引用图谱可以临时从当前 workspace 生成。
    大规模图谱和搜索应改用派生索引。


6. 命名规则

    WorkspaceRepository、WorkspaceFileStore、WorkspaceApiServer 表示仓库级持久化链路。
    NoteRecord、NoteTree、NoteEditor、NoteOutline 只用于单篇笔记或笔记结构语义。
    WorkspaceSyntaxFile 表示仓库唯一语法文件，不表示多 profile 列表项。
    useWorkspaceController 是 workspace 应用层 facade。
    useRepositorySession 管理 repository session、加载、保存、刷新和语法文件 API。
    domain 表示纯规则和纯数据变换。
    workspace 表示前端应用编排、当前会话上下文、view model 和 workflow。


7. 重要 workflow

加载：

    useRepositorySession -> WorkspaceRepository -> HTTP Adapter -> Node API -> File Store
    File Store 读取 workspace.json、notes/*.ctn、syntax/workspace.toml。
    前端把语法 profile 注入运行时 workspace。

编辑：

    UI 触发 command。
    useWorkspaceController 调用 domain 或 workspace workflow。
    workspace 更新后进入自动保存队列。
    后端校验 payload 后写回权威文件。

解析：

    parsedNoteView 读取 workspace.syntaxProfile。
    profile 有效时调用 CTN parser。
    profile 无效时返回错误 view model。

块迁移：

    workspaceBlockMigration 使用同一份 workspace.syntaxProfile 解析源笔记和目标笔记。
    成功时更新源笔记、目标笔记、activeNoteId 和更新时间。
