工程架构


文档职责：

    记录稳定工程架构、源码目录、数据流、存储边界和模块职责。
    不记录产品愿景、功能需求细节、个人环境、当前主线、当前 TODO 和近期任务顺序。


1. 运行形态

当前支持的运行形态：

    浏览器前端
    本机 Node HTTP 后端
    本地文件仓库

桌面路线：

    当前架构不维护 Tauri 桌面运行层。
    如需恢复桌面路线，应作为独立运行形态重新评估。

Docker 路线：

    Docker 属于 HTTP 后端的部署形态。
    它不改变 Browser React UI、Node HTTP API 和本地文件仓库的职责边界。


2. 总体分层

整体链路：

    Browser React UI
        |
        v
    Workspace 应用层
        |
        v
    Domain Layer
        |
        v
    CTN + Syntax Core
        |
        v
    Storage Port
        |
        v
    HTTP Adapter <-> Node HTTP API <-> File Store

分层职责：

    Browser React UI 负责交互、布局和视图状态。
    Workspace 应用层负责 session、command 编排、parsed note view model 和功能 workflow。
    Domain Layer 承载笔记、目录树、块文本、块迁移等可测试规则。
    CTN Core 只解析 .ctn 原文，产出块、行内结构、诊断和范围信息。
    Syntax Core 负责语法 profile、TOML 解析、TOML 校验、默认语法和默认 TOML 序列化。
    Storage Port 由 WorkspaceRepository 表示，前端只依赖该端口。
    HTTP Adapter 把 WorkspaceRepository 调用转为 HTTP 请求。
    Node HTTP API 和 File Store 负责安全读写本地文件仓库。

原则：

    影响数据正确性的规则不放在 React 组件中。
    UI 只负责选择、展示和触发 command。
    Domain 和 Workspace 应用层应优先可单元测试。
    CTN 解析器必须显式接收 CtnSyntaxProfile，不负责选择或兜底语法。
    Syntax 模块是前端 TypeScript 里的语法 profile、profile 类型和默认语法权威来源。


3. 源码目录

    src/app/
        React 应用入口和主工作区组合。

    src/features/
        按功能划分的 React 工作区界面。
        当前包含 notes、syntax、migration。

    src/shell/
        应用外壳、左侧活动栏和仓库侧栏。

    src/workspace/
        Workspace 应用层。
        负责 repository session、workspace commands、workspace syntax 解析、parsed note view model 和功能 workflow。

    src/domain/
        领域规则。
        负责 notes、noteTree、noteBlockText、noteBlockMigration、workspaceActions。

    src/ctn/
        CTN 原文解析核心。

    src/syntax/
        语法 profile、TOML 解析、校验和默认语法资源。

    src/editor/
        CodeMirror 6 集成层。

    src/storage/
        前端存储端口和存储适配器。

    src/styles/
        全局样式和按区域拆分的 CSS。

    server/
        Node HTTP API 和文件仓库读写逻辑。

    tests/
        顶层测试目录，按模块边界组织。


4. 前端应用层

src/app/：

    组合主工作区、侧栏、功能面板和右侧详情区。
    不直接实现领域规则。

src/features/：

    notes 负责笔记编辑区和结构树。
    syntax 负责语法 TOML 编辑和语法详情。
    migration 负责跨笔记块迁移界面。
    feature 组件不直接处理数据正确性规则。
    具体 notes、syntax、migration、outline 面板属于 feature UI。

src/shell/：

    负责全局导航、活动栏、仓库侧栏和当前功能入口。
    shell 只应承载应用外壳、导航、活动栏和布局容器。
    知道具体业务功能的 sidebar 组件不应长期停留在 shell。

src/workspace/：

    useRepositorySession 负责加载、保存、刷新、切换仓库路径和语法文件 API。
    useWorkspaceController 保留为 facade，组合 repository session、当前选择状态和 workspace commands。
    syntaxResolution 统一处理 workspace 中的 syntax profile resolution。
    syntaxResolution 只把 note/workspace 引用解析为 resolved、missing-profile 或 invalid-profile 状态，不解析 TOML。
    parsedNoteView 统一处理“笔记 + workspace -> 解析视图模型”。
    workspaceBlockMigration 负责跨笔记块迁移完整 workflow。


5. 领域层

src/domain/notes.ts：

    定义 NoteRecord、NoteWorkspace、NoteTreeNode 等基础模型。
    提供笔记标题推断和初始 workspace 结构。
    不负责语法 profile 查找、校验或默认语法选择。

src/domain/noteTree.ts：

    负责文件夹和笔记树规则。

src/domain/noteBlockText.ts：

    负责文本块范围、提取、删除、插入和缩进改写。

src/domain/noteBlockMigration.ts：

    负责单次块文本迁移规则。
    不依赖 workspace、React 或 repository。

src/domain/workspaceActions.ts：

    负责 workspace 级笔记、文件夹和语法切换变换。
    由调用方传入 id 和 timestamp。

domain / workspace 判断标准：

    只需要普通对象作为输入，并返回普通对象或失败结果的纯规则，优先放 domain。
    需要 repository、session、active note、syntax file list、UI 错误状态或多个模块调用顺序的逻辑，放 workspace。
    能脱离应用直接测试的逻辑应尽量下沉到 domain。
    描述一次用户操作要串起哪些步骤的 workflow 留在 workspace。


6. CTN 与 Syntax 边界

三类解析必须分开：

    syntax/*.toml 解析归属 src/syntax，输入 TOML 原文，输出 CtnSyntaxProfile。
    .ctn 原文解析归属 src/ctn，输入 note.source 和 CtnSyntaxProfile，输出 CtnDocument。
    syntax profile resolution 归属 src/workspace，输入 NoteWorkspace 和 NoteRecord，输出 resolved、missing-profile 或 invalid-profile 状态。

src/ctn/：

    只解析 .ctn 原文。
    只消费 CtnSyntaxProfile。
    只拥有 CTN 解析结果类型，例如 CtnDocument、CtnBlock、CtnDiagnostic。
    不负责语法文件读取、默认语法生成、语法选择和存储。

src/syntax/：

    拥有 CtnSyntaxProfile、CtnMarkerRule、CtnInlineRule 等 profile 类型。
    负责默认语法 profile。
    负责 TOML profile 解析、格式化、校验和运行时 shape 检查。
    不解析 .ctn 笔记原文。

第一版 TOML schema：

    根字段为 id、name、version、spaceIndentUnit、markers、inlineRules。
    id 和 name 必须是非空字符串。
    version 和 spaceIndentUnit 必须是正整数。
    markers 必须是非空数组。
    marker rule 字段为 marker、type、label、role、tone。
    marker 不允许重复。
    type 必须是 ASCII kebab-case 机器语义 ID。
    role 只能是 normal 或 code。
    只有 role = "code" 的 marker 触发 fenced code block。
    tone 只能使用 default、green、blue、amber、red、violet、code。
    inlineRules 必须显式提供，空数组表示禁用所有行内结构。
    inline rule 支持 paired 和 single。
    schema 之外的字段必须拒绝。

服务端：

    server/syntaxProfileToml.mjs 当前保留独立 Node 实现。
    tests/syntax/syntaxProfileTomlParity.test.mjs 用于固定前后端 TOML 解析、格式化和默认 profile 的一致性。
    是否共享 TS schema 或迁移 server 到 TS，不在当前架构中承诺。


7. 存储边界

前端存储端口：

    WorkspaceRepository 是前端唯一存储端口。
    HTTP WorkspaceRepository 是标准实现。
    localStorage WorkspaceRepository 仅作为显式开发备选。

后端职责：

    提供 HTTP API。
    安全读写本地文件仓库。
    保存和读取 workspace 前校验 workspace manifest / payload DTO。
    校验语法文件。
    保护被引用语法文件不被删除。

后端不负责：

    编辑器交互规则。
    UI 视图状态。
    CTN 文本编辑行为。


8. 命名边界

持久化链路：

    WorkspaceRepository、WorkspaceFileStore、WorkspaceApiServer 使用 Workspace 命名。
    原因是它们负责完整 workspace persistence，包括 workspace、repository info、syntax file CRUD，而不是单篇 note。

Note 命名：

    NoteRecord、NoteTree、NoteEditor、NoteOutline 等 Note 命名只用于真实单篇笔记、笔记树、笔记编辑和笔记结构语义。
    不再用于仓库级持久化端口、文件仓库实现和 HTTP API server。

SyntaxProfileFile：

    SyntaxProfileFile 暂时保留。
    它表示语法 profile 文件，不是 workspace persistence port。
    只有语法文件模型语义变化时，才重新评估是否改为 SyntaxFile。

应用层 hook：

    useWorkspaceController 表示 workspace 应用层 facade，向 UI 暴露命令和当前选择状态。
    useRepositorySession 表示 repository session，负责加载、保存、刷新、路径和语法文件 API。

目录命名：

    domain 当前表示纯规则、纯模型和纯数据变换。
    workspace 当前表示前端应用编排、当前会话上下文、view model 和 workflow。
    两者命名维度不完全一致；目录层级命名变更必须作为独立架构重构处理。


9. 文件仓库模型

稳定工程模型：

    NoteWorkspace
    NoteRecord
    NoteTreeNode
    CtnDocument
    CtnBlock
    CtnSyntaxProfile
    CtnMarkerRule
    CtnInlineRule

权威源文件：

    workspace.json
    notes/*.ctn
    syntax/*.toml

workspace.json：

    保存 workspace 元信息。
    保存 activeNoteId。
    保存 defaultSyntaxProfileId。
    保存 notes 元信息。
    保存目录树。
    读取时必须符合当前 manifest DTO；旧 schema 或损坏数据显式报错。

notes/*.ctn：

    保存每篇笔记原文。

syntax/*.toml：

    保存仓库可用语法资源。
    workspace.json 不作为语法 profile 的权威来源。

后续索引：

    index.sqlite 可作为派生缓存。
    FTS5 可用于全文搜索。
    索引缓存不替代权威源文件。


10. 数据流

加载：

    useRepositorySession 调用 WorkspaceRepository。
    HTTP adapter 请求 Node API。
    File Store 读取 workspace.json、notes/*.ctn、syntax/*.toml。
    前端把语法 profile 注入 workspace。

编辑：

    UI 触发 command。
    useWorkspaceController 调用 workspace action。
    workspace 更新后自动保存。
    WorkspaceRepository 写回后端文件仓库。
    后端保存前校验 PUT /api/workspace payload，非法 payload 不应覆盖已有 workspace。

解析：

    parsedNoteView 根据 note.syntaxProfileId 和 note.syntaxVersion 找 profile。
    找不到 profile 时返回错误视图模型。
    profile shape 非法时返回错误视图模型。
    profile 有效时调用 CTN parser。

块迁移：

    UI 选择源笔记、源块、目标笔记和目标位置。
    源块选择应基于源笔记结构树，并展示将被移动的整棵子树。
    目标位置选择应基于目标笔记结构树，并展示插入到文末根块或某块之后。
    workspaceBlockMigration 解析源笔记和目标笔记。
    目标语法不支持源块子树 marker 时返回失败。
    成功时更新源笔记、目标笔记、activeNoteId 和更新时间。
    拖拽式迁移只作为输入方式，不替代 workspaceBlockMigration workflow。
