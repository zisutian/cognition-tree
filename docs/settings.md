# 设置操作

设置采用与笔记、日记、代办相同的对象关系：左侧选择，主区处理，右侧查看已保存的相关详情。
右栏可以折叠，认证、一次性密钥、撤销和迁移恢复均可在主区完成。

## 选择与保存

| 目录分组 | 可选择的对象 |
|---|---|
| 界面 | 工作台布局 |
| 服务 | 网络访问、路径显示、所有者凭据、数据迁移 |
| 智能体 | 默认会话配置、本地服务发现、每个 Provider 和 Profile |
| API 访问 | 每个自动化令牌、可信客户端令牌 |
| 审计 | 操作记录、保留策略 |

目录组可以折叠；这不会切换当前对象，也不会丢弃表单。设置标题右侧的刷新按钮重新读取已保存状态。
设置表单统一采用标签在上的纵向布局。枚举使用下拉框，布尔项使用复选框，允许的仓库使用复选框组。
选择具体对象会直接打开表单。Provider、Profile 和令牌使用各自目录组的 `+` 创建。
需要提交的表单使用主区标题旁的保存与“放弃修改”；目录标记和底栏会提示未处理状态。
有未保存输入、配置基线过期或正在提交时，不能切换设置对象或离开设置，问题定位也遵守同一限制。
保存或放弃后，自行再次选择目的地；系统不会自动执行先前被阻止的跳转。

刷新设置不会替换未保存输入。配置已被外部修改或对象已删除时，保留当前输入并说明原因；
请先自行复制仍需保留的输入，再明确放弃，载入最新配置。过期后即使改回旧值，也需要明确放弃并重新载入。保存失败也会保留表单。
右侧显示的是已保存事实，编辑中的新值仍在主区。

“工作台布局”和“默认会话配置”即时生效；筛选及本地服务发现地址无需保存。
未提交表单和密钥不写入浏览器持久存储。刷新或关闭网页不保留设置草稿，也不显示离开弹窗。

## 网络、路径与审计

“网络访问”调整访问范围、端口和 HTTPS 公开地址；“路径显示”设置宿主机显示路径。
每页保存只表达本页修改，其他配置以该表单的有效基线保留。
需要重启的配置、部署方式和默认值见[部署与恢复](deployment.md)。

“操作记录”在主区浏览记录，右侧查看所选记录；技术标识默认折叠。
“保留策略”单独修改保留数量，缩小后会裁剪最旧的展示记录。

## 所有者凭据

远程使用步骤：

1. 从本机打开“设置 → 服务 → 所有者凭据”，准备 owner credential；此时旧凭据仍然有效，新 secret
   尚不能认证。
2. 保存持续显示在界面中的新 secret，并明确点击“我已保存，激活新密钥”。
3. 激活成功后再配置 HTTPS public origin 与局域网模式，等待服务重启。
4. 远程浏览器输入已激活的 secret；服务换发最长 12 小时的
   `ctn_owner_session` Cookie。

准备和激活分为两步。主区显示新密钥及激活按钮；离开此对象或关闭显示会清除页面明文，
服务端尚未激活的轮换仍保留。重新准备会替换该轮换。激活结果未知时先保留密钥，再按页面说明
刷新或重新登录；不要重复提交以猜测结果。清除凭据需要在本机模式下就地确认。

## 数据迁移

在“服务 → 数据迁移”填写不存在的目标绝对路径，点击开始并就地确认。
主区展示阶段、源与目标位置、权威目录是否已确认、恢复原因和可执行动作。
刷新设置或重启后会重新查询持久记录。迁移的先决条件、数据保留和异常处理见
[部署与恢复](deployment.md#数据控制区与迁移)。

## 令牌

在“自动化令牌”或“可信客户端令牌”目录组点击 `+`，填写名称及适用的权限和仓库范围，
然后从标题操作区创建。成功后目录选中新对象，明文密钥只在主区显示一次；保存后关闭显示。
离开该对象或活动也会清除页面明文。选择已有令牌可以查看权限及最近使用情况，撤销需要就地确认。
两类令牌的权限差异和外部调用方法见[API 与 CLI 集成](api-integration.md)。

## Agent Provider 配置与认证

Provider 表单采用纵向字段，类型和认证使用下拉框，私网许可使用复选框。编辑已有服务时，API Key 留空会保留已保存的密钥。

Provider、Profile 和凭据只在“设置 → 智能体”管理。secret 以 0600 服务状态保存，
响应永不回传；这依赖操作系统文件权限，不承诺静态加密。

loopback Provider 自动允许。非 loopback 私网 origin 必须在创建或每次修改 Provider
时显式确认；许可固定到 Provider version、digest 与精确 origin。修改 endpoint 会让
许可和旧符合性结果失效。metadata、link-local、unspecified、multicast，以及 DNS
同时解析到不同安全类别的目标始终拒绝。带凭据的远程 Provider 必须使用 HTTPS。

“会话历史预算（字符）”控制 Cognition Tree 何时压缩驻留内存中的对话历史，并限制
单次响应与工具增量在途累计的字符数；不会向 Ollama 发送 `num_ctx`，也不表示模型的
真实 token 上限。需要观察模型事实时，
点击对应 Provider 的“探测”：Ollama 会为该 Provider 已配置 Profile 所引用的模型显示
“模型架构上限”“当前驻留上下文”和探测时间；模型未加载时明确显示无法测量实际值，
已加载但接口缺字段时显示未报告。探测不发送推理请求、不加载模型、不延长驻留，结果
也不持久化、不自动填写或裁剪 Profile。

符合性检查会显示“等待工具调用”“等待自然语言总结”和“记录结果”阶段，并可在记录
结果前取消。大型本地模型可能需要数分钟；浏览器通过状态轮询观察检查，不受普通 API
请求的 30 秒上限截断，模型本身仍受该 Profile 的 timeout 限制。检查使用真实的
Workspace 新建笔记 schema，并同时提供一个干扰读取工具；假 handler 不会创建内容、
staging 或 proposal。当前检查依次验证读取检查专用的写作指南、正确单工具调用和
后续自然语言总结；因此 chat Profile 的“最大工具步骤”不能小于 3。

本版本的 Agent tool contract 已升级。现有 chat Profile 会因旧符合性 digest 失效而
暂时 unavailable；升级并重启 Cognition Tree 后，在“设置 → 智能体”重新执行一次
符合性检查即可继续创建新会话。检查不会写入仓库内容。

Ollama 发现只在用户点击后执行，默认地址是 `http://127.0.0.1:11434`。认知树只调用
模型层 `/api/tags`、显式探测所需的 `/api/ps` 与 `/api/show`，以及推理所需的
`/v1/chat/completions`；不调用另一个代码 Agent 的任务、MCP、Git 或 shell API，
也不接管 Ollama 生命周期。

Ollama chat Profile 的推理强度可选“模型默认、关闭、低、中、高”。“模型默认”不发送覆盖
参数，其余值映射到 Ollama 请求的 `reasoning_effort`；运行时不会
按模型名称自动修改或 fallback。模型的原始 reasoning 只为当前工具循环保留在内存，
不会显示、持久化或进入审计。输出因长度耗尽、过滤、缺少终止帧或空回复结束时，会
产生 Agent Problem，不会被当作成功，也不会隐藏重试。

### Codex 认证

先创建 `kind: codex` 的 Provider，并只选择一种认证方式：

- API Key：在设置中一次性写入。新会话通过 app-server 登录协议注入临时认证，不把
  key 放入 shell、MCP 或子进程环境。
- ChatGPT 设备码：创建 Provider 后点击“使用 ChatGPT 登录”，打开设置显示的 HTTPS
  地址并输入设备码。登录可取消，默认 15 分钟后自动过期；成功后只显示“认证已配置”。

“退出认证”是唯一清除入口。会话正在创建、已经 resident 或设备码正在登录时，切换
对应 Provider、退出认证、删除 Provider 和数据根迁移都会被拒绝。若登录的配置提交
结果未知，界面会要求重启后再确认；此时不会删除可能已经生效的登录态。ChatGPT 登录态保存在应用管理的
`agent-auth-v1`，不读取个人 `~/.codex`。每个 Cognition Tree 会话仍创建独立 app-server
进程和 `ephemeral` thread，不导入或继续 Codex Desktop/CLI 历史。
