# 测试指南

本文件说明验证边界、项目入口和结果解释。模块约束见[模块边界](architecture.md)，
运行包构建与恢复见[部署与恢复](deployment.md)。

## 分层与夹具

| 层次 | 证明的事实 | 入口 |
|---|---|---|
| 单元 | 领域规则、状态机、协议、呈现语义 | `tests/unit`，内部镜像生产职责 |
| 集成 | 真实磁盘、HTTP、CAS、锁、权限和进程恢复 | `tests/integration` |
| 结构 | 模块唯一归属、公开入口、依赖图与样式所有权 | `tests/architecture` |
| 文档 | 本地链接、锚点、脚本与命令入口 | `tests/documentation` |
| 浏览器流程 | 点击、键盘、焦点、导航、保存、冲突、认证 | `e2e/flows` |
| 浏览器布局 | 几何、对齐、滚动、遮挡和长内容 | `e2e/layout` |
| 容量与性能 | 同配置的耗时、内存、分析复用与结果完整性 | `tooling/benchmark` |

共同夹具放在 `tests/support`，浏览器服务与造数放在 `e2e/support`；只供单个测试族使用的
HTTP、文件系统和进程辅助与测试族共置。测试文件不充当其他测试的公共入口。

每个浏览器 worker 使用独立服务、随机端口和临时目录，每个用例重新造数，避免顺序依赖。
服务准备等待真实入口的静态依赖就绪，活动仍按实际懒加载路径打开；初始化和交互预算分开记录。
测试或准备阶段失败同样释放已登记的连接、服务和后台任务。

模型夹具提供确定性协议，配置、HTTP、存储、审批和提交仍走真实路径；这不代表真实模型通过验证。
凭据流程关闭 trace、截图和自动错误快照，断言只输出安全结果；布局截图使用合成数据。

## 针对性验证

按实际受影响边界选择入口：

    pnpm test:unit
    pnpm test:integration
    pnpm test:architecture
    pnpm test:docs
    pnpm test:e2e:flows
    pnpm test:e2e:layout

`pnpm test` 包含全部 tests，`pnpm test:e2e` 包含流程与布局；分层入口用于缩小反馈范围。
具体测试路径从相应目录选择，不按历史修复任务另建验证入口。

| 变更 | 必须关注的行为 |
|---|---|
| 保存与内容会话 | 并发草稿、真实冲突、恢复失败、解决期间所有修改入口暂停、完成后继续编辑 |
| 设置与导航 | 草稿保护、过期基线、迟到响应、创建与删除、关闭及恢复焦点 |
| 共享 UI 与编辑器 | 现有调用方业务流程、输入法、撤销、选区、保存前 flush、审批及危险确认 |
| 布局与目录 | 框架默认密度、窄分区、缩放、长标题、独立滚动、键盘及弹层焦点 |
| 文件与进程 | 真实写入、锁释放、迁移中断、重新打开存储与磁盘结果 |

浏览器默认尺寸由 [Playwright 配置](../playwright.config.ts)确定；其他尺寸和环境通过对应
布局用例或任务验收要求覆盖。比较框架实际布局和相对关系，不锁定旧控件尺寸或内部 CSS。

## 完整验收

首次准备浏览器后按顺序运行完整检查：

    pnpm test:e2e:install
    pnpm check
    pnpm test
    pnpm build
    pnpm test:e2e
    pnpm benchmark:capacity
    git diff --check

`test` 已包含结构和文档检查；`build` 包含前端、包体积检查与服务端编译。
提交钩子独立检查类型和架构，但不代替行为验收。独立运行包的验证见下节。

Vitest 与 E2E 的并发、超时和浏览器默认值分别由工程配置拥有；更改 `--maxWorkers` 或
`CTN_E2E_WORKERS` 时记录采用值，不把不同配置混作同条件对照。
验收说明应区分合成模型、真实模型、进程中断、真实断电和不同平台的证据范围。
历史报告不作为测试前置条件，也不代表当前工作树已通过验收。

## 本机内容接口回归

| 边界 | 验证位置与重点 |
|---|---|
| 用例 | `tests/unit/application/content`：名称、Unicode、路径、歧义、身份复用与版本 |
| 存储 | `tests/integration/server/operations`：真实收据、幂等、旧账本迁移、容量与中断恢复 |
| HTTP/CLI | `tests/integration/server/api/localContentApi.test.ts`、`tests/integration/tooling/cli`：实际请求、标准输入、错误解码与不重放 |
| OpenAPI | `tests/unit/contracts/openApi.test.ts`：共享引用、递归 schema、错误收据与 registry 一致 |
| 浏览器 | 仓库操作版本冲突、提交后刷新失败、收据查询及恢复操作 |

准备失败不得放行新提交，提交已完成但刷新失败不得重做写入。
静态输出不能证明恢复成功：存储层检查重新打开后的磁盘事实，浏览器检查对象可见、
版本缺失时禁止新写入、刷新后恢复操作。认证回归验证旧令牌拒绝及历史状态保留。

## 性能变更验证

容量使用 `pnpm benchmark:capacity`；局部热点使用
[整体优化基准](../tooling/benchmark/overallOptimization.ts)。先核对结果与行为，再比较相同数据、
配置和环境下的耗时。预热后多次采样，报告中位数与范围，保留数据规模、内存、实际结果和校验次数。
读取次数等探针与普通计时分开，不将微基准推断为整库固定加速比例。

基线和对照顺序执行，避免与构建、全量测试或浏览器任务竞争资源。数据规模、并发或超时改变后
重新说明比较范围，不能通过降低容量、增加重试或放宽门槛取得通过。

行为等价重点包括身份与分析复用、实际字节改变后的文件发现、Unicode 与字素位置、
来源故障后的搜索和分页恢复、Todo 局部与完整查询一致。准备耗时和交互耗时独立解释。

## 独立运行包验收

    pnpm test tests/integration/tooling/runtime

集成验证双入口参数、开发配置保留、重启退出、文件和权限、越界链接、监听冲突、未知文件保护、
完整备份与安装中断恢复，使用真实临时目录和子进程。

另在独立临时源码副本验证开发 `./start.sh` 的健康、网页与内容调用；生成候选包后使用
`pnpm release:smoke <候选目录>` 验证编译入口，不启动正式数据或替换可用版。
运行包应脱离源码、Vite、TypeScript 与 pnpm 验证网页、API、CLI 和 Agent 子进程入口。
冒烟涵盖 CLI 读取、创建、精确编辑、重复请求与结果查询，以及旧 Bearer 拒绝；不复制正式凭据。

## 新增或整理测试时

共享状态机在生产所有者处完整验证，领域 wrapper 验证接线和领域差异。
静态输出验证可访问关联、禁用语义与敏感内容隐藏；点击、键盘、焦点和几何在浏览器验证。
结构守卫表达长期禁止的类别，不积累退役函数、路径和选择器清单。
结构约束保持声明式，规则目录与检测器分离；跨域共同约束由共享所有者提供，
避免多个检查器各自维护同一套规则。

每个场景只准备自己的业务前提，共享夹具不隐藏领域规则或预期结果。
异步验证等待状态、响应或几何稳定，请求延迟门控在失败时也释放，不靠固定暂停或串行化掩盖耦合。
删除重复测试时确认保留的验证位置，不能将行为断言降为“输出非空”或另一种实现形状检查。
