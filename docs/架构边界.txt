架构边界


1. 模块职责

app：

    应用组合根，装配 application、ui、storage 和 editor。

application：

    workspace 应用层，管理 session、命令流程、加载保存、页面状态、视图选择和 UI 投影。

ui：

    workbench 界面层，组合活动栏、槽位布局、activity 页面、共享组件和样式系统。

workspace：

    workspace 业务核心，承载数据模型、命令、查询、索引和语法上下文。

ctn：

    CTN 核心能力，承载原文解析、结构诊断、引用解析、块文本编辑和 syntax profile。

storage：

    前端持久化端口和实现，以带仓库位置和 revision 的仓库快照统一读取 workspace 数据与仓库语法 source，并提交完整内容新版本。

editor：

    编辑器技术适配，承载 CodeMirror 组件、扩展、装饰、诊断提示和语法展示。

server：

    本机 HTTP API 和文件仓库执行端，负责请求处理、DTO 校验、版本冲突检测、仓库快照事务和本地文件布局。


2. 依赖方向

    app -> application、ui、storage、editor
    ui -> application、editor
    application -> workspace、ctn、storage
    workspace -> ctn
    storage -> workspace
    editor -> ctn
    server -> Node HTTP、文件系统、本地文件仓库 DTO


3. 数据流

    server 从本地文件仓库生成包含仓库位置、workspace、syntax source 和 revision 的完整快照，并以事务提交完整新版本。
    storage 将仓库快照和提交结果转换为前端 repository 契约，过期 revision 不覆盖当前仓库。
    application 维护 session 和单一保存队列，调用 workspace 命令并生成 UI 需要的 view model。
    ui 根据 view model 渲染 workbench，并通过回调触发 application 命令。
    editor 接收 ui 和 application 给出的文本、诊断和语法展示数据。
    workspace 和 ctn 负责结构、语义和派生数据的确定性计算。
