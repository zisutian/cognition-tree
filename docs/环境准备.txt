环境准备


1. 基础工具

当前项目使用 Node.js、pnpm、Vite、Vitest 和 TypeScript。

推荐工具：

    Node.js 22.x
    pnpm 11.1.3
    Git 2.x

依赖安装：

    pnpm install

本地 Git hooks：

    pnpm hooks:install

package.json 固定的包管理器为 `pnpm@11.1.3`。


2. 本机后端

启动命令：

    pnpm server

默认地址：

    http://127.0.0.1:3001

默认仓库根目录：

    .cognition-tree/repositories

默认服务端状态目录：

    .cognition-tree/server

后端环境变量：

    CTN_API_HOST
    CTN_API_PORT
    CTN_REPOSITORY_ROOT
    CTN_SERVER_STATE_DIR
    CTN_WEBDAV_PRIVATE_TARGETS
    CTN_PUBLIC_URL
    CTN_API_TOKEN

后端提供 health、repository catalog 和按 repository id 访问的 snapshot API。`GET /api/repositories` 列出仓库与单仓问题，`POST /api/repositories` 创建 Local 仓库或注册 WebDAV 连接，`GET/PUT /api/repositories/<repositoryId>/snapshot` 读取或提交指定仓库，`DELETE /api/repositories/<repositoryId>?mode=...` 删除托管内容或移除连接；base revision 过期时返回 409，且不覆盖已发布内容。所有仓库 ID 由 catalog 自动生成，格式为 `repository-<lowercase-uuid>`；新建内容中的 workspace ID 独立生成为 `workspace-<uuid>`。repository id 只映射到 catalog 管理的对象，不接受前端指定的文件路径。

HTTP 模式在设置页中动态注册和切换 Local/WebDAV 仓库。WebDAV 表单包含稳定名称、URL、无认证或 Basic 认证；Browser 存储模式只显示 Browser adapter，不从浏览器直接连接 WebDAV。仓库切换不复制、上传或合并 Local 与 WebDAV 内容。

WebDAV registry 位于服务端状态目录：

    <CTN_SERVER_STATE_DIR>/webdav-connections/<repository-id>.json

状态目录及连接目录权限为 `0700`，连接配置和原子写临时文件权限为 `0600`。每个 schema version 1 配置独立保存 repository ID、稳定 label、规范化 URL、认证方式和 `active` 或 `deleting-remote` 状态。Basic 密码只存在于服务端连接文件和请求 Authorization header，不进入 repository 内容、API 响应、日志、浏览器设置或 IndexedDB。服务启动只加载 registry，不访问 WebDAV 网络；离线连接仍出现在 catalog 中，已有 IndexedDB 副本仍可打开。损坏的单个连接文件形成可清理的 WebDAV 问题，registry 根目录、锁和权限异常会使后端启动失败。

初次添加连接执行完整能力探测，包括 ETag、If-Match、If-None-Match、PROPFIND、MKCOL、PUT、GET 和 DELETE。完全空的目标使用表单生成的初始 v3 内容初始化；已有合法 v3 内容保持为远端事实；v2、非空 unmanaged target 和 deletion tombstone 不会被初始化。WebDAV adapter 在 `.ctn-generations/<token>/` 中写入不可变 generation，以 `.ctn-lock.json` 的 60 秒 writer lease 协调写入，并通过 `.ctn-current.json` 的 ETag CAS 发布 generation。同一 server state 中一个规范化 WebDAV URL 只对应一个连接。

带 Basic 认证的 WebDAV URL 使用 HTTPS。URL 不包含 userinfo、query 或 fragment；请求拒绝 3xx，不读取代理环境变量，使用 30 秒完整 deadline，并把单次响应限制在 20 MiB。生产请求在每次访问前重新解析全部 A/AAAA 地址，混合允许与禁止地址的结果整体拒绝；实际 socket 固定到已验证地址，同时保留原 hostname 的 Host、SNI 和证书校验。

WebDAV 目标地址默认限于 global-unicast。`CTN_WEBDAV_PRIVATE_TARGETS` 接受由逗号或空白分隔的精确 origin 与 CIDR：

    CTN_WEBDAV_PRIVATE_TARGETS='https://nas.example:5006,192.168.1.0/24 fd00::/8'

精确 origin 只包含 `http` 或 `https` scheme、host 和显式或默认 port，path 为 `/`，且不包含 userinfo、query 或 fragment。CIDR 同时支持 IPv4 与 IPv6。匹配项授权私网、loopback、ULA 和 CGNAT 地址；link-local、metadata、unspecified、multicast、broadcast、文档网段和 reserved 地址不受该白名单覆盖。

Local 和 Browser adapter 只接受 `delete-managed-data`。WebDAV 的 `remove-connection` 排空当前 store 后删除本地连接配置并保留全部远端内容；`delete-managed-data` 先将连接持久化为 `deleting-remote`，再取得 writer lease，以旧 current ETag 的 CAS 发布包含 deletion token、时间和原 revision 的永久 tombstone。CAS 之后只清理 `.ctn-generations/`，目标中的无关文件和 `.ctn-current.json` tombstone 保留。清理暂未完成时 API 返回 `202 {"status":"deleting"}`，catalog 显示 deleting issue，并按固定退避或重启恢复继续清理。移除 deleting issue 的本地连接配置会停止跟踪，远端可能保留不可达 generations。

旧的 `CTN_WEBDAV_REPOSITORIES` 静态配置入口不参与读取或迁移；环境中定义该变量时后端启动失败。

真实 WebDAV 协议验收命令为 `pnpm verify:webdav:live`。该命令在 loopback TCP 端口启动文件系统落盘的 WebDAV 服务，通过生产 HTTP transport 验证条件请求、不可变 generation、两个 writer 的 lease fencing、断线重连、提交与读取交错一致性，以及默认 60 秒 lease 下持续超过一分钟的提交和续租；因此执行时间至少为一分钟。日常 `pnpm test` 保留快速单元回归，但不执行这项长时 live 验证。

浏览器 Origin 默认允许：

    http://127.0.0.1:5173
    http://localhost:5173

默认 loopback 绑定只接受 `127.0.0.1`、`localhost` 和 `::1` Host，不要求 bearer token。绑定到非 loopback 地址时，必须同时配置至少 32 字符的 `CTN_API_TOKEN` 和 HTTPS `CTN_PUBLIC_URL`；可使用 `openssl rand -hex 32` 生成 token。服务端从公开 URL 推导唯一允许的 Host、Origin 与 CORS 响应，不记录 token，也不把 token 写入仓库。


3. 前端开发服务

启动命令：

    pnpm dev

默认地址：

    http://127.0.0.1:5173

连接本机后端：

    VITE_CTN_API_BASE_URL=http://127.0.0.1:3001 pnpm dev

连接要求 bearer token 的后端：

    VITE_CTN_API_BASE_URL=http://api.example.test:3001 VITE_CTN_API_TOKEN=<token> pnpm dev

使用浏览器存储：

    VITE_CTN_STORAGE_MODE=browser pnpm dev

HTTP 模式连接服务端管理的 Local 与 WebDAV 仓库。浏览器存储模式提供同样的多仓库 catalog 语义，用于界面和交互验证。每个浏览器独立保存当前 repository id。

`VITE_CTN_API_TOKEN` 会由浏览器作为 Authorization bearer 发送，只用于 API 请求；它不写入 repository catalog、workspace、IndexedDB cache 或日志。作为前端构建变量，它对使用该浏览器构建的人可见，因此安全边界仍是单用户部署和受控前端环境。

HTTP 模式会在 IndexedDB v3 中按 API origin、repository id 和 token digest 隔离缓存，以 normalized stores 保存 catalog、repository state 和逐笔记 source。编辑事务同时执行 expected local revision CAS、笔记增删改与 state 更新。连接中断后，已有缓存的仓库可以在页面刷新后继续打开和编辑；连接恢复会立即尝试同步。如果远端 revision 已变化，则保留并继续接受本地 pending 内容。设置页的“放弃本地修改”只有在成功读取远端后才原子清除 pending。


4. 数据文件

本地文件仓库包含：

    repository.json
    snapshots/<sha256-revision>/workspace.json
    snapshots/<sha256-revision>/notes/*.ctn
    snapshots/<sha256-revision>/syntax/workspace.toml

`repository.json` 使用 schema version 3，保存稳定 catalog label 和当前 revision。revision 指向不可变 snapshot；`workspace.json` 保存 workspace 身份和目录树，笔记 source 写入 `notes/<noteId>.ctn`，可选仓库语法写入 `syntax/workspace.toml`。提交先完整写入并 fsync staging snapshot，再原子发布 snapshot 和 head；repository root 由单个 server writer 持有进程级锁。

canonical 笔记 source 始终以标题块元数据行和标题内容行开头。每个 CTN 块的同缩进 `@ctn-block` 元数据包含稳定块 ID、创建时间和更新时间；编辑区显示 editable source，普通文本中的同名行不会被静默删除。笔记标题可以为空并产生诊断，只有 canonical 元数据结构损坏时拒绝加载。

没有语法的仓库仍可在笔记活动中以原始模式编辑 `.ctn` 文本；结构操作和引用图谱保持不可用。语法只在语法活动中显式创建，打开仓库不会自动生成默认配置。

旧 Local manifest、browser storage、HTTP cache 和 WebDAV control file 不读取、不转换，也不自动备份；发现旧格式时报告 `unsupported_repository_version`。空仓库只由 catalog create 创建，普通 load 不会隐式补齐缺失内容。


5. 验证命令

TypeScript：

    pnpm check

测试：

    pnpm test

浏览器端到端测试：

    pnpm test:e2e

端到端测试使用独立的 3317 API 和 4174 前端端口，按编辑、目录与结构操作、语法与图谱、全局诊断、仓库与容量流程分别造数；不复用日常开发仓库。

构建：

    pnpm build

diff 空白检查：

    git diff --check

架构边界测试：

    pnpm test:architecture

后端 TypeScript 检查：

    pnpm exec tsc -p tsconfig.server.json --noEmit

后端生产构建与启动：

    pnpm server:build
    pnpm server:start


6. 双端使用

Linux 作为主要开发、测试和后端运行环境。Windows 可通过浏览器访问同一个本机后端服务，用于检查界面、输入法、路径展示和数据互通。

两端代码仓库可以分别存在。笔记数据以 HTTP catalog 当前仓库指向的 Local snapshot 或 WebDAV generation 为准。项目目录使用普通英文路径，仓库文件使用 LF。
