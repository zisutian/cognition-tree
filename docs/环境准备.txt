环境准备


1. 基础工具

当前项目使用 Node.js、pnpm、Vite、Vitest 和 TypeScript。

推荐工具：

    Node.js 22.x
    pnpm 11.1.3
    Git 2.x

依赖安装：

    pnpm install

本地 Git hooks：

    pnpm hooks:install

package.json 固定的包管理器为 `pnpm@11.1.3`。


2. 本机后端

启动命令：

    pnpm server

默认地址：

    http://127.0.0.1:3001

默认仓库根目录：

    .cognition-tree/repositories

后端环境变量：

    CTN_API_HOST
    CTN_API_PORT
    CTN_REPOSITORY_ROOT
    CTN_API_ALLOWED_HOSTS
    CTN_API_ALLOWED_ORIGINS
    CTN_API_TOKEN
    CTN_WEBDAV_REPOSITORIES

后端提供 health、repository catalog 和按 repository id 访问的 snapshot API。`GET /api/repositories` 列出仓库，`POST /api/repositories` 创建仓库，`GET/PUT /api/repositories/<repositoryId>/snapshot` 读取或提交指定仓库；base revision 过期时返回 409，且不覆盖磁盘内容。repository id 只映射到配置根目录的直接子目录，路径规范化和真实目录检查由 server 执行。

WebDAV 仓库通过服务端 JSON 配置，例如：

    CTN_WEBDAV_REPOSITORIES='[{"id":"remote","label":"远端仓库","url":"https://dav.example/notes/","username":"user","password":"secret"}]'

地址与凭据只由 server 读取，不写入仓库文件或前端设置。WebDAV adapter 使用直接的 `workspace.json`、`notes/` 和 `syntax/` 布局；隐藏 lock、staging 和 journal 只用于多文件提交与中断恢复，成功后删除。本地仓库与 WebDAV 仓库之间不传输或合并内容。

浏览器 Origin 默认允许：

    http://127.0.0.1:5173
    http://localhost:5173

使用其它前端地址时，通过逗号分隔的 `CTN_API_ALLOWED_ORIGINS` 显式配置。带 Origin 的非白名单请求会被拒绝；本机命令行请求可以不携带 Origin。

默认 loopback 绑定只接受 `127.0.0.1`、`localhost` 和 `::1` Host，不要求 bearer token。绑定到非 loopback 地址时，`CTN_API_TOKEN` 必须至少包含 32 个字符；可使用 `openssl rand -hex 32` 生成。绑定到 `0.0.0.0` 或 `::` 时必须通过逗号分隔的 `CTN_API_ALLOWED_HOSTS` 明确列出浏览器实际发送的 Host，可包含端口。服务端不记录 token，也不把 token 写入仓库。


3. 前端开发服务

启动命令：

    pnpm dev

默认地址：

    http://127.0.0.1:5173

连接本机后端：

    VITE_CTN_API_BASE_URL=http://127.0.0.1:3001 pnpm dev

连接要求 bearer token 的后端：

    VITE_CTN_API_BASE_URL=http://api.example.test:3001 VITE_CTN_API_TOKEN=<token> pnpm dev

使用浏览器存储：

    VITE_CTN_STORAGE_MODE=browser pnpm dev

HTTP 模式用于真实本地文件仓库。浏览器存储模式提供同样的多仓库 catalog 语义，用于界面和交互验证。每个浏览器独立保存当前 repository id。

`VITE_CTN_API_TOKEN` 会由浏览器作为 Authorization bearer 发送，只用于 API 请求；它不写入 repository catalog、workspace、IndexedDB cache 或日志。作为前端构建变量，它对使用该浏览器构建的人可见，因此安全边界仍是单用户部署和受控前端环境。

HTTP 模式会在浏览器 IndexedDB 中保存每个 API 地址对应的最近确认 catalog，以及每个 repository id 对应的最近确认快照。连接中断后，已有缓存的仓库可以在页面刷新后继续打开和编辑，并以单个最新 pending commit 取代更早的待同步内容。连接恢复时，如果远端 revision 未变化则自动提交；如果远端已变化，则保留本地内容并进入冲突状态。设置页的“放弃本地修改”会先删除 pending commit，再重新读取远端内容。


4. 数据文件

本地文件仓库包含：

    workspace.json
    notes/*.ctn
    syntax/workspace.toml

`workspace.json` 使用 schema version 2，保存仓库、目录树和笔记元信息。笔记稳定写入 `notes/<noteId>.ctn`，目录层级只由 manifest tree 表达；重命名笔记或目录不改变笔记文件路径。`syntax/workspace.toml` 保存仓库语法 source。

配置语法的仓库会在每个 CTN 块前保存同缩进的 `@ctn-block` 元数据行，其中包含稳定块 ID、创建时间和更新时间。保留行不显示在编辑区；编辑结果保存时由 application 合并回持久化原文，块时间在笔记详情中独立展示。没有语法的仓库保留原始文本，不初始化块元数据。

没有语法的仓库仍可在笔记活动中以原始模式编辑 `.ctn` 文本；结构操作和引用图谱保持不可用。语法只在语法活动中显式创建，打开仓库不会自动生成默认配置。

未版本化仓库不由运行时直接读取。停止使用目标仓库的后端后，执行：

    pnpm repository:migrate-v2 -- /absolute/path/to/repository

迁移命令先创建同级完整备份，在临时目录生成并校验 v2，再原子切换目录；失败时目标仓库保持原状。


5. 验证命令

TypeScript：

    pnpm check

测试：

    pnpm test

浏览器端到端测试：

    pnpm test:e2e

端到端测试使用独立的 3317 API 和 4174 前端端口，按编辑、目录与结构操作、语法与图谱、全局诊断、仓库与容量流程分别造数；不复用日常开发仓库。

构建：

    pnpm build

diff 空白检查：

    git diff --check

架构边界测试：

    pnpm test:architecture

后端 TypeScript 检查：

    pnpm exec tsc -p tsconfig.server.json --noEmit

后端生产构建与启动：

    pnpm server:build
    pnpm server:start


6. 双端使用

Linux 作为主要开发、测试和后端运行环境。Windows 可通过浏览器访问同一个本机后端服务，用于检查界面、输入法、路径展示和数据互通。

两端代码仓库可以分别存在。笔记数据以 HTTP 后端指向的仓库路径为准。项目目录使用普通英文路径，仓库文件使用 LF。
