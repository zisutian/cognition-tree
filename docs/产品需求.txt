产品需求


1. 产品定位

认知树是本地优先的可配置语法结构化笔记系统。

它面向概念、定义、组分、理解、引用和结构整理。`.ctn` 原文是写作和存储的主要格式；Markdown、HTML、PDF 和纯文本属于导出方向。


2. 核心对象

仓库：

    长期知识域，持有笔记原文、目录树和仓库语法。仓库只持久化真实事实；标题与时间从 canonical 笔记 source 推导。Local 仓库以真实目录和 `<标题>.ctn` 作为可见工作树，以根部 `.ctn/` 保存身份、顺序、语法、块元数据和事务事实。HTTP 模式的仓库可以由 Local 或动态注册的 WebDAV adapter 提供，Browser 模式使用独立的 Browser adapter；adapter 之间不自动传输内容。repository ID 由 catalog 自动生成，workspace ID 独立生成。

文件夹：

    仓库内的组织节点，用于浏览、归类、移动和新建落点。

笔记：

    一个相对完整认知对象的原文内容单元。应用内 canonical source 以标题 metadata 和标题内容行开头；标题与创建、修改时间均从该 header 推导。Local 的可见 `.ctn` 文件只保存编辑器正文，文件名去掉扩展名后与首行标题一致，canonical metadata 由隐藏 sidecar 重建。空标题可作为 draft 和诊断保留，但不能发布为 Local 文件。

块：

    由一行及其缩进子树组成，是阅读、选择、移动和结构整理的基本单位。配置语法后，每个块具有稳定标识、创建时间和更新时间；这些持久化元数据不占用编辑区域。

语法配置：

    符号解释方案，决定顶格无符号行、行首规则、行内规则、多行块、显示名称、缩进显示宽度和视觉提示。普通笔记仓库保存多份可切换的语法文件；日记和代办系统仓库各保存一份固定所有者、可编辑的语法配置。

引用：

    局部概念引用和全局概念引用。全局概念引用形成笔记级引用图谱；重复标题目标是 ambiguous 候选，不生成任意确定边，自引用保留为 self-loop。

日记条目：

    全局日记系统仓库中的手动记录单元。稳定 entry ID、创建时刻、创建时保存的 ISO 方向时区偏移、修改时刻、不可变当日序号和 canonical CTN source 是持久化事实。内容同时保存 `dailyCounters: [{ date, lastIssuedSequence }]`；标题固定为 `YYYY-MM-DD-0001`，每天从 `0001` 开始，删除后不复用序号，每天最多创建 9999 条。标题不能重命名，编辑器只暴露正文。

代办事项集合：

    全局代办系统仓库保存有序事项集合，每个集合是一篇以集合名为标题的 canonical CTN。Todo v2 持久化一份 `syntaxSource`、有序 collection 的稳定 ID 与 source，以及按块 ID 保存的 `completions: [{ blockId, completedAt }]`。任务文本、顺序和父子层级来自 CTN，完成状态只来自 sidecar；完成项保持原位置，源码不改写为 `[x]`。


3. 产品特征

思维优先：

    编辑器围绕概念结构和思维链路组织，而不是围绕版式排版组织。

缩进即作用域：

    缩进表达父子关系、展开关系和局部语义范围。

符号即语义：

    行首符号、行内符号和多行块符号映射为明确的语义类型。

仓库级语法：

    一个普通仓库保存多份有序语法文件。点击文件只打开编辑，当前启用项由独立的“用”操作改变；新建语法复制当前编辑文件、只选中而不自动启用。日记和代办的单份系统语法在同一语法活动中编辑，但不能新增、删除、重命名或切换版本。

本地优先：

    用户持有完整笔记原文、目录结构和语法配置。Local 仓库中的界面文件夹与磁盘目录一致，界面笔记与标题命名的 `.ctn` 文件一致。

原文权威：

    语法配置影响解析和显示，笔记原文保持独立。

开放数据：

    Local 可见内容由普通目录和 `.ctn` 正文组成；仓库内部事实由根部 `.ctn/` 中的 JSON、TOML、sidecar 和 WAL 组成，便于检查并保持事务一致性。

可移植名称：

    普通笔记标题、文件夹名、仓库名和 Todo 集合名采用 Obsidian 友好的严格可移植规则：存储前执行 `trim → NFC → 连续 ASCII 空格折叠`，只允许 Unicode 字母、组合标记、数字、内部普通空格、`-` 和 `_`。唯一性与引用键使用 `NFKC → en-US lowercase`；新建和重命名立即拒绝非法名称，既有非法名称保持可读并形成诊断，不自动改写。语法 profile 名称和任务正文不使用该规则。

个人仓库：

    产品面向单个使用者及其受控设备。服务端 bearer token、WebDAV 凭据和 writer fencing 保护个人部署与同一使用者的多个实例；产品对象中没有用户、角色、共享权限或多人协作状态。


4. 当前范围

已具备能力：

    在仓库活动中创建、选择和切换 Local/WebDAV 仓库；在 Browser 模式创建、选择和切换 Browser 仓库。
    为 repository 自动分配稳定 ID，并为初始内容独立分配 workspace ID。
    动态注册无认证或 Basic 认证的 WebDAV 连接；空目标初始化为 v4 仓库，已有 v4 内容保持为远端事实。
    删除 Local/Browser 托管数据；对 WebDAV 分别提供仅移除连接和删除远端托管数据。
    远端删除通过 ETag CAS 发布永久 tombstone，随后清理托管 generations，并保留目标中的无关文件。
    将 Local 文件夹和笔记投影为真实目录与 `<标题>.ctn`，并在首次加载、同步和手动重新扫描时识别外部新增、编辑、删除、重命名和移动。
    使用 Local 隐藏顺序清单保留同级手工排序；保留非 `.ctn` unmanaged 文件，并阻止界面整体删除包含 unmanaged 文件或 symlink 的目录。
    创建、编辑、删除、重命名和移动笔记。
    创建、重命名、删除和移动文件夹。
    编辑 CTN 原文，并用 Tab 表达结构层级；在多行块内保持代码内容缩进，不改变 CTN 结构。
    在保留活动栏的专注模式中编辑当前笔记，并在退出后恢复原有工作台布局。
    用仓库语法解析整个仓库，在编辑器中装饰当前笔记并展示结构树。
    在笔记详情中分别查看笔记的创建与修改时间，以及当前结构块的创建与更新时间。
    在语法活动的“系统语法”和“笔记库语法”分组中编辑配置；普通语法的编辑选择与启用状态分离，系统语法固定为日记和代办两项。
    在源笔记和目标笔记之间移动整棵块子树。
    在单篇笔记内调整结构块位置。
    通过 Ctrl+点击跳转局部块引用和全局笔记引用，并在多目标时明确选择落点。
    查看笔记级引用图谱和局部引用关系。
    在工作台全局问题面板中按活动查看问题并定位目标：普通活动使用 workspace diagnostics；Repository 合并 workspace、普通/系统仓库和名称问题；Journal 使用正文、语法、仓内及跨仓引用诊断；Todo 使用语法和 CTN 诊断；Syntax 使用当前编辑 owner 的 profile 诊断，并按 owner 附加对应仓库诊断；Settings 不挂载 Problems。
    在紧凑 master-detail 仓库活动中创建、内联重命名、选择、切换和删除普通仓库。左侧依次显示“内置”、新建仓库操作行及 Local、WebDAV、Browser 分组，只保留图标、名称和极简状态；选中非当前仓库后以行内“开”切换，当前项显示“当前”。右侧集中显示只读 ID、adapter、结构化位置、复制、重扫、重试、清理、移除连接、停止跟踪、删除和手工删除说明。新建表单也显示在右侧，成功后停留在仓库活动并选中新仓库。
    普通笔记标题、文件夹名、仓库名和 Todo 集合名执行统一严格可移植名称校验；“日记”和“代办”是仓库保留名。descriptor 以 `labelIssue: conflict | reserved | nonportable | null` 投影既有问题，既有不合规名称保持可读并要求手工重命名。
    固定提供全局唯一的日记和代办系统仓库。系统仓库独立于当前普通仓库和 WebDAV，不能创建第二份、删除、重命名或切换为普通当前仓库。Journal 与 Todo 使用各自 v2 contract 和按 purpose 管理的 epoch；发现缺失或旧 v1 epoch 时无提示清除该 purpose 的旧内容及 local-first draft/cache，再创建空 v2。已进入 v2 后的损坏内容和未知未来版本保持原样并显示故障与重试。
    手动创建一天多条日记，按创建时保存的年月分组并在组内按创建时间倒序显示；进入日记时选择最新条目，删除确认后选择相邻条目。
    日记 v2 保存可编辑的独立 `syntaxSource`；顶格无符号行按中性的 `body` 正文规则解析，不显示概念强调，受保护的 `[[...]]` 引用规则保持可用。标题使用创建日期和不可复用的当日序号。`[[YYYY-MM-DD-0001]]` 引用日记仓内条目，`[[仓库名:笔记名]]` 按需读取命名普通仓库的 local-first snapshot，只解析 canonical note header，不解析概念块、Todo 或其他系统仓库，并支持从问题或引用跳转切换普通仓库与笔记。仓库或笔记重命名不自动改写独立 CAS 中的日记原文，跨仓边也不并入普通仓库引用图谱。
    Todo v2 以 CTN 编辑事项集合正文，缩进正式表达父子任务；受保护的 `todo-item` 语义规则默认使用 `[]`，其名称、符号和颜色可配置，但 ID/role 不可删除或改变。编辑器和详情结构树均可勾选，状态写入 completion sidecar；块移动和缩进保留完成状态，删除源码块清理孤立 completion。
    事项集合可新建、内联重命名、删除并通过拖动或键盘排序。任务不增加跨 collection 移动、截止日期、优先级、备注或筛选；Todo 挂载自身语法与 CTN Problems。
    无效语法草稿不持久化，并阻止离开当前语法；主面板提供“撤销无效更改”。仓库和语法的行内按钮只在对应行被选中时渲染，不因悬停或单纯聚焦出现。
    在仓库活动中手动重新扫描当前仓库；外部修改不通过 watcher 或 SSE 实时推送。
    在 catalog 中分别呈现健康仓库、损坏连接和仍在执行远端清理的条目，不让单仓问题阻断其他仓库。
    在网络不可用时继续编辑已有缓存的远端仓库，并在恢复后自动同步或明确报告 revision 冲突。

保留入口：

    搜索。
    数据视图。

后续能力：

    全文检索、导出、导入、反向链接、派生索引、全文统计、同步、插件、桌面封装和 AI 辅助整理。

复杂图谱能力：

    概念级图谱、块级图谱和时间演化图谱。


5. 语法范围

默认语法：

    顶格普通行：顶格概念
    :：定义
    >：自我理解
    -：组分、分类、例子和枚举项
    ?: 疑问
    ```：多行块
    `...`：行内代码
    <...>：局部概念引用
    [[...]]：全局概念引用
    \：并列分隔

仓库语法覆盖：

    顶格概念名称。
    行首规则名称、符号和颜色。
    行内规则名称、符号和颜色。
    多行块规则名称、符号和颜色。
    Tab 显示宽度。

仓库语法边界：

    缩进层级和父子关系来自原文结构。
    一个普通仓库可以保存多份有序语法文件；列表选择只决定编辑目标，启用状态由独立命令改变。
    语法名称在仓库内按 trim、NFKC 和 en-US lowercase 规范化后唯一。
    单篇笔记和单个文件夹没有独立语法。
    普通笔记正文不内嵌语法配置。
    语法界面只暴露受控字段、受控颜色和受控规则类型。

系统语法边界：

    日记保存一份固定所有者的可编辑语法；顶格无符号行使用中性的 `body` 规则，`[[...]]` 引用规则受保护。
    Todo 保存一份固定所有者的可编辑语法；顶格无标记正文不合法并形成诊断，`todo-item` 规则的语义 ID/role 受保护，默认符号为 `[]`，名称、符号和颜色可配置。
    日记和代办语法不能新增、删除、重命名或切换版本。


6. 成功状态

    用户可以不用 Markdown 记录复杂概念笔记。
    用户可以用缩进表达作用域和层级。
    用户可以维护多份仓库级语法并明确选择当前启用项。
    用户可以通过结构树判断笔记结构。
    用户可以在笔记之间移动整棵块子树。
    用户可以在单篇笔记内整理结构块。
    用户可以通过引用图谱查看笔记间关系。
    用户可以直接检查仓库中的原文、目录和语法文件。
    用户可以在不切换普通仓库的情况下记录多条固定当日序号标题的结构化日记，并从日记引用和打开任意命名普通仓库中的笔记。
    用户可以在不切换普通仓库的情况下用 CTN 层级维护独立、有序且可持久化的事项集合，并在正文与结构树中共享勾选状态。
