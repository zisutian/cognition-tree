# 界面规范

本文件拥有工作台的视觉和交互契约；模块依赖与生命周期见 [架构说明](architecture.md)。

## 1. 视觉基础

采用紧凑的桌面工具布局。保留活动导航和左侧上下文、中部内容、右侧详情三大区域；笔记目录保留原有行结构、层级、选中反馈和操作顺序。内部部件可按统一模板组合，不增加页面独有的控件外观。

所有基础值由 [theme.css](../presentation/ui/styles/foundation/theme.css) 定义：

| 项目         | 规范                                                   |
| ------------ | ------------------------------------------------------ |
| 界面字体     | 系统字体，13px，行高 1.4                               |
| 编辑正文     | 14px，行高 1.5；代码使用等宽字体                       |
| 字重         | 普通 400、强调 600；标题不额外放大                     |
| 间距         | 元素内 4px、控件间 8px、区域内边距 12px、分组间 16px   |
| 标题与工具栏 | 分区标题 40px；工具栏最小 36px，可为长内容换行         |
| 普通控件     | 28px；多行输入和换行选项按内容增高                     |
| 列表         | 22px 固定行高，目录层级缩进 14px                       |
| 图标         | 普通操作 16px、活动导航 24px；列表标记延续 13px        |
| 圆角         | 普通控件 6px；大区域保持平直                           |
| 阅读宽度     | 表单、会话正文最大 720px；文档、结果与画布使用可用宽度 |

表单内容与分区标题使用同一左边界。会话转录和输入区保持相同阅读宽度并居中。图谱、语法标记、行差异的内容几何由其专用实现拥有，不得借此修改通用控件。

## 2. 分区与模板

`ActivityRegionSlot` 对三大区域使用相同声明：title、actions、toolbar、content、footer、layout。`AppFrame` 管理区域组合、调整尺寸、折叠、专注模式；`RegionFrame` 统一呈现标题、操作位、工具栏、边界和留白。同级标题共享基线，标题仅标识对象或区域，操作向右排列。

`Page` 组合正文与操作，`PageBody` 从区域继承唯一的 layout 声明，提供正文滚动与 form、results、table、detail、document、conversation 布局。`Section`/`SectionStack` 统一分组；ToolToolbar、ToolPropertyList、ToolList 分别持有筛选、静态属性、结果行。活动不能重写公共头部或重新增加一层面板壳。

主区、侧栏和详情保持独立滚动；固定的输入与审批操作位于滚动正文之外。图谱和编辑器填满剩余空间。内容较少时也保留相同边距，不通过额外卡片填充空白。

标题和必要字段名称保留；重复界面标签、操作说明、引导段落和教程式空状态删除。空状态只包含简短状态及必要操作。错误、未保存、冲突和危险操作的必要信息保留。用户正文、来源内容和差异正文不属于界面文案清理范围。

## 3. 控件、列表与编辑

Button、InputControl、SelectControl、TextareaControl、CheckboxControl、CheckboxGroup、ChoiceGroup、RangeControl、ColorControl、ToggleButton 是普通 React 操作和表单控件的唯一所有者。公开接口提供语义变体与 sizing，不开放 className、style 或裸按钮变体。内部列表通过受控的紧凑操作接口维持 22px 行高。

功能、单选、多选与复选标签共享中性灰选中底色、6px 圆角和状态反馈。未选中时透明，hover 时轻灰；不使用拼接边框或蓝色下划线。蓝色保留给主要操作和键盘焦点。选中、焦点、拖动及诊断是不同状态。单选保留 radiogroup、方向键与 Home/End；多选保留独立切换；禁用项不可激活。复选框的点击区域包含标签，长标签自然换行。

FormLayout 统一让输入填满字段列；FieldRow、FormActions 统一字段标签、错误关联及操作排列。分组字段使用 aria-labelledby，错误通过稳定 ID 和 aria-describedby 关联。移除解释性说明槽位。窄表单转为上下排列，长值占据自身列，不撑开页面。

CompactContextList 只服务上下文目录；ManagementList 保留主区管理语义；ToolListRow 区分单行与自然换行结果。禁止因视觉相似合并领域状态。目录行只在 selected 时显示动作，顺序为辅助操作、重命名、删除；hover 或 focus 不额外展示动作。重命名保持原行，Enter 提交、Escape 取消，失焦不提交；失败保留编辑状态并报告错误。删除确认在相同动作区呈现。

树与 Problems 的窗口化保留固定 22px 行高，超过既有阈值时继续使用窗口化。目录树与结构树共享测量规则，不共享业务命令。结构缩进沿用现有语义配置，拖放保留上方、下方和内部落点。

CodeMirror 保留输入法组合、编辑历史、光标、诊断和导航。笔记模式切换通过隐藏保留编辑视图，不能卸载后重建编辑器。CodeMirror checkbox 与 React checkbox 共享同一视觉类契约，各自拥有 DOM 生命周期与命令适配。CTN 语义色不受界面选中颜色影响。

## 4. 样式所有权

共享组件和活动使用所属模块的 CSS Modules；共享组件不导入活动或编辑器实现。全局样式仅包括主题、reset 和受控 CTN 内容适配。

共享组件通过自身样式绑定提供外观。contentClasses 是语义内容标记到共享模块的显式绑定入口；可读 DOM 类名用于诊断，不能作为跨组件覆盖入口。活动样式仅覆盖自己创建的内容元素；禁止 `.activity label`、`.activity .ui-*` 等穿透公共组件的选择器。按钮和输入的状态仅由各自实现定义，禁止在页面重新定义字号、圆角或选择色。

弹层由共享 Overlay/Popover 管理外壳、视口避让、焦点恢复、Escape 和外部点击。小型选择器与常规面板使用明确尺寸变体，活动只提供内容。阴影仅用于浮层；正文不增加装饰性卡片边框、分隔线或用户气泡。

## 5. 验收

使用合成数据覆盖全部八个活动及认证、问题面板和弹层。在 1280×720、1440×900、缩放和窄分区条件下检查：标题基线、尺寸、留白、字体、选择状态、操作对齐、长文本、独立滚动和无页面级横向溢出。

检查空、加载、错误、禁用、未保存和冲突状态；保持输入、重命名、拖放、导航保护、保存冲突、会话隔离以及 Agent 审阅行为。颜色选择、焦点返回和固定底部操作需在浏览器中验证。

设计契约检查约束唯一所有者与样式边界；浏览器检查测量真实几何并生成页面截图。类型与单元测试通过不能替代视觉验收。验证仅在开发环境与临时候选包上执行，不使用真实笔记、凭据或正式数据生成截图。
