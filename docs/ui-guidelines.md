# 界面规范

本文件只定义信息排布、交互、尺度、颜色和共享 UI 结构。产品能力见
[产品需求](product-requirements.md)，状态所有权和数据流见
[架构边界](architecture.md)，CTN 分析语义见
[CTN 分析流水线](ctn-analysis-pipeline.md)。


## 1. 基准

界面采用 VS Code Dark Modern 的工作台方向：平面、克制、高信息密度、低装饰。Workbench 由活动栏、上下文区、主工作区、可选详情区、独立 Problems 面板和全宽状态栏组成。`ActivitySlots` 返回 null 的槽位不渲染；Activity 明确提供的紧凑空状态属于真实内容，AppFrame 不自行补占位。

笔记是文档编辑型页面样本，并在内部承载结构整理和引用图谱模式。其他页面只复用合适的视觉结构，不复用无关业务模型。


## 2. Activity 布局

智能体：

    左侧只显示与仓库/笔记列表同密度的内存会话和唯一新建 `+`；profile、认证、刷新和硬范围表单不放在侧栏。
    点击 `+` 后在主区以“使用的 Profile / 硬范围”两个紧凑分区创建会话；只展示设置中显式选择的默认 profile，不在此切换。Workspace folder/note 细粒度范围只在对应仓库已加载时可选。
    对话标题栏固定显示 Profile、模型和运行状态，取消操作也只位于标题栏。主区按事件 sequence 增量增长对话，正文限制阅读宽度；composer 固定在主区底部，帮助文字与发送动作共用一行。不显示 raw chain-of-thought。
    右侧在选中会话且有实际 Proposal 时显示；未选择会话、创建会话或尚无提案时省略空详情栏。存在 proposal 时，顶部显示人类目标、状态和资源变更数；中部独立滚动并显示资源路径、中文动作摘要、块计数和带前后行号的正文 diff，不显示资源 ID 作为标题。删除警告保持醒目；整批批准/拒绝或 destructive confirmation 固定在右栏底部，不随长 diff 滚出视野。base revision、digest、资源/块 ID、change set 和字符级 diff 放入默认关闭的“技术详情”；长标识显示前后各 8 位并可复制完整值。多份 Proposal 用“序号 · 状态 · 人类目标名称”选择。

笔记：

    上下文区显示目录；主区显示完整可编辑笔记；详情区显示统计、笔记时间、结构和当前块时间。
    编辑模式的“文件”分组标题右侧只使用图标，从左到右固定为“重新扫描文件、新建文件夹、新建笔记”。扫描期间三个按钮禁用；失败进入全局 Problems。
    canonical 标题行使用加粗字重，概念强调仍由语义类型独立决定。
    左侧标题下使用共享 ChoiceGroup 的轻量外观在“编辑、结构、图谱”之间切换，保持 radiogroup 的方向键及单一 Tab 焦点语义。模式、图谱筛选/设置以及图谱视口在当前页面会话内按仓库保留，仓库之间不得共享坐标缓存；编辑面板在模式切换时保持挂载，当前笔记、光标和撤销历史不重置。结构模式显示双文档结构操作；图谱模式显示引用画布和节点详情。

日记：

    左侧是不可编辑的“年 → 月 → 条目”树，不显示“日”分类。进入时选择最新条目并展开年、月；新建和问题跳转同样展开目标路径。
    条目固定标题显示在面板标题中，CodeMirror 只编辑正文。选中条目后可在原行“删 → 确认/取消”。
    顶格无符号行是中性 body。详情区显示正文统计、条目时间、当前块时间和正文结构。

代办：

    左侧是可新建、内联重命名、删除和排序的事项集合，不显示分组或条目计数；集合整行使用共享列表拖拽及上方/下方落点，不显示专用拖拽按钮。主区只编辑所选集合正文；右侧显示同一 CTN 的任务结构。
    [] 渲染为 checkbox，缩进表示父子任务。完成项原位划线，不写回 [x]。
    右侧复用共享结构树的缩进、选中、诊断和行号样式，marker 位置只显示 checkbox；任务只允许勾选和定位，不提供拖动。

语法：

    左侧先列出系统语法，再列出笔记库语法，不显示“系统语法 / 笔记库语法”可见标题或计数；新建按钮位于两类列表之间并左对齐。选中普通语法只打开编辑；行内“用”才改变启用项。当前启用项用固定前导状态图标替换文件图标，不在行尾重复“启用”文字。仓库与语法的小按钮只在该行 selected 后渲染。
    语法名称只在左侧列表和主区标题显示，重命名只发生在左侧原行；右侧基础设置不重复名称字段。
    日记与代办只显示实际可见正文相关规则；synthetic title 是内部解析事实，不出现在系统语法表格或预览。
    普通笔记语法仍显示标题规则。无效草稿存在时禁止离开，并提供“撤销无效更改”。
    行内规则表只显示一个“颜色”；它只染色符号和下划线，行内正文继承块文字色，预览与编辑器保持相同语义。
    所有背景选择器的第一个预设为“编辑器背景”，色块直接使用 --color-editor；标题、顶格规则、普通块和多行块的背景变更必须同步反映在语法预览与源码编辑器。
    不可删除规则不渲染垃圾桶。固定字段用普通只读文字展示，不使用禁用输入框或禁用下拉框；同一行的可编辑字段仍使用正常控件。Todo 内置“代办”固定名称、[] 和普通块类型，只开放背景与颜色；用户新增的 Todo 块仍显示完整字段与删除入口。

编辑器：

    kind 为 multiline 的块与其他 CTN 内容一样显示完整源码。opener、正文、空行和 closer 不投影为卡片，不隐藏、不保护、不增加视觉缩进补偿，也不插入规则名称。
    multiline lexical 范围仍使用命中规则的 tone 和 textColor；opener marker、正文及 closer 的颜色由同一规则控制。规则 label 只作为语法和结构元数据名称。
    Tab、Shift+Tab、Enter、删除、复制、粘贴和多行选区遵循 CodeMirror 的普通文本编辑行为。单光标 Tab 只影响当前行，选区操作只影响实际选中行；编辑器不自动移动或删除完整 multiline 块。
    闭合与未闭合 multiline 块都保持可见源码；未闭合块同时显示诊断，用户可直接编辑围栏和缩进修复。
    Workspace、Journal 或 Todo 进入同步冲突后，正文 CodeMirror 继续允许编辑；冲突面板投影当前仍需处理的单元。全部冲突消除后自动同步并关闭冲突提示。执行显式解决动作的短暂期间才冻结编辑，以保护该次 revision proof。
    普通列表选中态只使用中性背景或文字变化，不绘制左侧蓝色强调条。只有诊断行允许左侧状态条；诊断状态条保持原有 3px 宽度、上下留白和右侧圆角，并固定使用错误色。

仓库：

    左侧顺序为“内置数据”日记、代办，以及唯一的“本地”分组。本地组底部只有一个 `+` 新建入口，即使没有仓库也保留；行内只保留图标、名称和极简状态。当前普通仓库使用固定前导状态图标，不在行尾追加“当前”文字。Server 不可用时显示失败和重试，不投影本地空仓库。
    选中普通仓库后才显示“开”和内联重命名；主区标题承担名称，优先提供“继续编辑笔记 / 打开仓库”，然后显示重试、冲突恢复和确认；删除放在末尾。右侧状态区以选中名称分组，并用共享属性表展示状态、ID、位置、路径、故障和冲突事实，复制按钮进入属性操作列；冲突事实显示远端 revision 与冲突单元，详情的加载、失败重试、空单元“整仓内容”必须明确区分。健康活动仓库的文件重扫只出现在笔记工具栏。
    选中内置数据后，右侧显示保存状态、位置和故障事实，主区提供可执行的重试或恢复动作；不提供删除、重命名或普通仓库切换。
    永久删除和故障清理都在主区危险分区原位展开确认；永久删除必须输入完整仓库名称，不使用确认弹窗。

其他：

    搜索左侧首行是查询框与图标提交按钮；只在 Enter 或该按钮时提交。范围只显示“本地仓库 / 日记 / 代办”三个多选分段，“本地仓库”代表全部普通仓库；不显示逐仓库列表、更多条件或时间限制。主区标题栏显示上次提交的搜索词；修改草稿或切换 Activity 后继续保留旧结果与滚动位置，并在条件变化时显示“条件已修改”。结果按资源分组，来源、仓库和更新时间作为次级元数据，整篇/块匹配使用固定 marker 列；未开始搜索时省略右栏，搜索后右侧显示已提交条件、资源数、命中数与来源故障，点击命中仍直接打开内容。
    设置左侧按“界面、服务、智能体、API 访问、审计”分组列出对象。组标题可折叠且初始展开；折叠只影响目录可见性，不改变当前对象或草稿。刷新位于设置标题右侧，Provider、Profile 和令牌的创建按钮位于所属目录组；选择对象后主区直接编辑，不重复显示分类标签或管理列表。审计记录在主区浏览，右侧跟随所选记录，不把记录展开进目录。
    设置标题操作区固定显示保存和放弃，正文滚动不会带走操作。未保存、基线过期或正在提交时，设置内部选择与离开活动均被阻止；底栏只提示持续状态，不提供保存、放弃操作或弹窗。保存、放弃或未过期草稿恢复原值后，用户自行重新导航，不重放被阻止的请求。外部更新和对象删除保留输入；一旦过期，改回旧值或后续刷新都不会解除限制，明确放弃后才重新载入。
    右侧只显示当前对象的已保存事实、关联对象和必要说明。界面偏好、默认 Profile、本地发现和新建表单没有有用详情时省略右栏。界面偏好和默认 Profile 即时生效；筛选、发现参数不构成配置草稿。
    所有者新密钥、ChatGPT 登录地址与设备码、令牌一次性明文、认证清除、撤销和迁移恢复都在主区可见，右栏折叠不影响操作。离开对应对象或关闭显示清除页面明文；未决服务端操作不会随页面卸载被取消。认证、迁移和撤销使用正文内确认。技术诊断默认折叠。
    chat Profile 字段固定命名为“会话历史预算（字符）”；Ollama 推理强度显示模型默认、关闭、低、中、高，其他 OpenAI-compatible Profile 不显示该字段。Provider 探测与符合性检查使用结构化状态摘要，默认 Profile 不自动回退。
    远程未登录时使用独立的 owner 登录门，不挂载工作台或提前加载内容；本机访问自动进入。数据迁移展示当前阶段、源与目标位置、提交结果、恢复原因及可执行操作；刷新后重新查询持久状态。权威未确认时保留维护提示，仅提供重新对账，不提供强制恢复。
    顶层 Activity 仅保留智能体、笔记、日记、代办、语法、搜索、仓库和设置，不渲染 Data 占位入口；底部顺序固定为智能体、搜索、仓库、设置。


## 3. Problems

Problems 位于主工作区底部，在所有 Activity（包括 Settings）使用同一个全局集合。
集合合并 Workspace、Journal、Todo 与 Syntax diagnostics、普通仓库和内置数据状态、
Agent 故障，以及 API、同步、设置和 UI action 的 operational incidents。切换 Activity
不隐藏其他来源问题；点击行再导航到拥有恢复能力的笔记、仓库、Agent 会话或来源
Activity。

状态栏固定在整个工作台底部，高度 22px。左侧显示错误、警告数量并提供问题面板开关；右侧优先显示当前活动的未保存、提交中或失败状态，无持续状态时显示最新的短暂反馈，随后恢复 Notes、Journal 或 Todo 的非稳定保存状态；稳定时为空，不显示“已保存”。右侧文本省略显示并提供完整提示，不挤压计数。

Problems 默认关闭，关闭时不占据编辑区。面板标题显示“问题”和关闭按钮；展开状态和高度在当前页面会话内按普通仓库保留，关闭再打开保留筛选。状态栏与面板消费同一个问题集合和状态投影，不各自维护保存状态。

面板使用共享紧凑工具栏提供来源、严重度和可重试性筛选，并使用共享 22px 紧凑工具行
展示架构边界定义的问题集合。操作错误显示重复次数、最近发生时间和“复制编号”，可以
独立关闭；状态型 diagnostics 不提供关闭。新错误不得自动展开 Problems，专注模式隐藏
面板但保留错误；右下角不渲染通知浮层，问题行不提供破坏性操作或 mutation 重试。


## 4. 尺度与字体

    活动栏宽度：48px。
    详情折叠宽度：36px。
    主工作区最小宽度：420px。
    面板标题高度：35px。
    面板内边距：10px；高密度正文节奏：4px。
    树行、输入框、选择、切换和按钮：22px。
    常规圆角：2px；活动按钮为连续 48px 点击区域。
    Problems 展开高度：120px 到 360px，默认 200px。

    面板标题：13px / 400。
    正文、列表、树：13px / 400。
    小标题、控件、辅助文字和代码：13px / 400 或 600。
    编辑器正文：14px；标题使用 strong-weight token。
    代码和符号：13px 等宽字体。
    数字：tabular-nums。

字号、字重和颜色必须通过角色 token 进入样式；Activity CSS 只描述布局和业务状态。
工具面板不重新定义表单字号、尺寸或密度。共享表单提供 columns 和 stacked 两种显式布局；纵向布局的控件高 26px、字段间距 16px，表单内容最大宽度 720px。所有设置对象统一使用纵向布局；枚举使用 SelectControl，布尔项使用 CheckboxControl，成员集合使用 CheckboxGroup。


## 5. 颜色与状态

工作台配色参考 [VS Code Dark Modern](https://github.com/microsoft/vscode/blob/main/extensions/theme-defaults/themes/dark_modern.json)。完整颜色、字体和尺度由 [theme.css](../presentation/ui/styles/foundation/theme.css) 唯一提供，页面不维护自己的颜色表。

活动栏、侧栏和底栏使用深灰，编辑区略亮；活动选中标记、主操作与键盘焦点统一使用蓝色。CodeMirror 的内容强调色和 CTN 语义颜色保持独立。selected、focus、drag 和 diagnostic 继续表达不同状态。面板通过背景、间距和位置分层，不为每个标题或列表行增加装饰性细线；阴影只用于菜单、tooltip 和浮层。

## 6. 共享结构

紧凑 context list：

    笔记、仓库、语法、日记和代办共享行操作与内联编辑结构，但保留各自 view model 与命令。设置复用受控分组、目录行、动作位和状态标记，不借用结构树的层级连接线。操作只在 selected 行渲染，hover 或单纯 focus 不显示。
    前导图标、主标签和行尾状态使用固定网格列并垂直居中；行尾多个状态必须包在同一对齐容器中。树内输入文字与行高垂直居中。
    操作固定右对齐，顺序为辅助操作、重命名、删除。笔记树的重命名与删除使用带名称和提示的图标；重命名在原行显示输入框和确认、取消动作，Enter 提交、Escape 取消、失焦不提交；删除在原操作区替换为“确认/取消”。切换选择必须取消未提交状态，失败时保留原地状态并把完整错误投影到 Problems。

结构树：

    用于笔记结构、语法预览和 Todo 详情。缩进随深度移动整行；marker 使用可变文本列。仅支持排序的业务树提供拖放并明确区分上方、下方和内部落点；Todo 详情只允许勾选和定位。

容量：

    树保持固定行高。可见行超过 500 时使用窗口化；窗口化只共享滚动与测量，不合并目录树和结构树的业务语义。

控件：

    InputControl、SelectControl、TextareaControl、CheckboxControl、CheckboxGroup、ChoiceGroup、RangeControl、ColorControl、Button 和 ToggleButton 是全软件表单与操作控件的唯一所有者；包括共享组件在内的普通 React 按钮都组合 Button，原生表单元素只由共享控件实现。Activity 不得直接渲染原生按钮或普通输入。CheckboxGroup 组合 CheckboxControl，拥有成员选择及标签布局；FieldRow 的 group 类型通过 aria-labelledby 关联组标题。ChoiceGroup 以判别联合分别提供单选 radiogroup 和多选 aria-pressed 语义。笔记模式选择保留 radiogroup 键盘语义；设置目录使用按钮导航，不伪装成标签页。CodeMirror 的 DOM checkbox 仅保留宿主生命周期、位置和领域命令适配，与 React checkbox 共用视觉契约；内容语义颜色保持独立。
    普通输入使用 content 尺度，从 72px 随值扩展并在 320px 封顶；结构输入使用 container 尺度占满容器。FormLayout、FieldRow 和 FormActions 统一拥有横向标签列、纵向标签布局、说明、错误关联和操作行；description 与错误分别获得稳定 ID 并通过 aria-describedby 关联控件。纵向表单输入使用 320px 阅读宽度，地址等长值显式使用 container 尺度。ManagementList/ManagementRow 独占主区管理列表，CompactContextList 继续只服务左侧上下文区，二者不得混用业务语义。
    FormSaveActions 和 FormError 统一提交展示与错误反馈，保存规则、版本判断和敏感操作仍由对应控制器拥有。RepositoryCreateForm 属于仓库，SyntaxUnavailablePanel 属于笔记，通用表单不包含领域呈现。
    StatusBadge 统一呈现状态；EmptyState 的 compact 模式用于详情栏和顶部对齐空白页。Activity 只组合业务布局、局部 presentation 状态和回调，不复制私有表单行或管理卡片。

CTN 文档：

    笔记、日记和代办保留各自的 view model、命令和编辑变更处理，但共享同一个编辑器面板壳与专注模式入口。笔记和日记的“统计、文档时间、当前块时间、结构树”共享同一个详情组件；Todo 右侧包含勾选与周期配置，继续保留独立业务组件。日记与代办未就绪时共享内置数据故障、重试和“前往仓库”页面，不复制状态分支与按钮组件。

工具页面：

    设置、仓库正文、搜索结果、智能体、语法和 Problems 采用统一工具界面层，共享页面壳、滚动容器、分区、筛选栏和基础结果行。CodeMirror 只用于真实文本编辑，不模拟这些结构化界面。PanelHeader 统一拥有面板与侧栏的固定标题和动作布局；ToolPanel 组合该头部与正文，不创建另一套标题或密度。ToolPanelBody 按 form、table、results、detail 四种内容类型分别限制为表单最大宽度、可用宽度、920px 和详情栏可用宽度。
    ToolSectionStack/ToolSection 统一表达弱化小标题、操作区和相邻间距，不提供通用解释性说明 API；ToolToolbar 负责紧凑筛选栏；ToolDivider 服务摘要栏、输入区和操作栏等固定边界。布局通过间距、对齐和位置分层，不新增装饰性细线，普通列表行之间不画线。
    ToolPropertyList/ToolPropertyRow 统一呈现工具页面中的静态“属性名—属性值”：使用语义化定义列表，属性名左对齐且不附加冒号；属性名列固定为 88px，属性值列占据剩余空间，可选操作列按内容宽度排列。属性行最小高度 22px、左右内边距 4px、列间距 8px；长值、代码和路径在值列内自然换行。属性行不提供 hover，也不绘制行间分割线，页面不得覆盖共享列宽。
    ToolListRow 必须显式选择 single-line 或 wrap：前者固定 22px 并截断，供窗口化 Problems 使用；后者最小 22px 并自然换行，供搜索结果和静态信息使用。静态行不得渲染伪按钮。Activity 样式只保留匹配列、严重度、diff、危险状态和窗口化定位等领域表达。
    智能体对话使用平铺转录，不使用用户气泡、右对齐或角色背景；角色标题弱化，消息和 Proposal 正文遵守同一 13px/4px 节奏，diff 只保留等宽字体和增删颜色差异。
    DetailPanel 是全部右侧详情栏壳与折叠按钮的唯一所有者，工具正文密度由 ToolPanelBody 提供。笔记、日记、代办、语法、智能体、搜索、仓库和设置都通过 ActivitySlots.detail 组合该结构，并由 AppFrame 的同一 onCollapseDetail 控制折叠；Activity 不得实现私有折叠按钮或第二套详情壳。


## 7. 桌面验收边界

本轮工作台只以桌面布局为契约。1280×720 与 1440×900 必须没有页面级横向溢出；左侧上下文区和右侧详情区继续使用 280px、320px 默认宽度并允许拖动调整，调整结果只属于当前页面会话。页面内部的目录、结果、对话、diff 与管理列表各自拥有滚动区，不能把长内容推给整个页面滚动。本规范不定义手机端或窄屏重排。
