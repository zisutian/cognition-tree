3. 近期实施顺序

3.1 仓库级可新增语法

目标：

    让每个仓库持有自己的 syntax/*.toml，并让每篇笔记独立指定语法 profile。

步骤：

    parseCtnDocument 必须显式接收 syntaxProfile。
    resolveWorkspaceSyntaxProfile 和 resolveNoteSyntaxProfile 不再静默 fallback。
    后端提供 syntax 文件列表、读取、保存和删除 API。
    保存 syntax TOML 前进行 schema 校验和重复 id/version 检查。
    删除被仓库默认语法或笔记引用的 syntax 文件时拒绝。
    前端语法面板支持 TOML 文件新建、编辑、保存和删除。
    编辑器支持当前笔记独立切换 syntaxProfileId 和 syntaxVersion。
    缺失语法时显示错误状态，不使用默认语法解析正文。

小提交顺序：

    显式 parser profile
    后端 syntax API
    前端 repository 和语法面板
    笔记级语法选择
    缺失语法状态

3.2 跨笔记块迁移底座

目标：

    支持不同笔记之间移动整棵块子树。

步骤：

    抽出块文本纯函数。
    实现跨笔记移动整棵块子树。
    移动前检查目标笔记语法兼容性。

3.3 块迁移 UI

目标：

    先验证流程，再接入拖拽。

步骤：

    增加双笔记结构面板。
    先做点击式“从左移到右”。
    再在同一套移动 API 上接入拖拽交互。

3.4 Docker 打包与部署验证

目标：

    将已经稳定的 HTTP 后端容器化，并验证 Docker volume 持久化。

步骤：

    增加 Dockerfile。
    增加 compose 文件。
    明确 volume 数据目录。
    验证容器重启后数据保留。
