2. 第一版闭环边界

第一版目标不是堆功能清单，而是先让核心认知树工作流闭合。

必须闭合：

    本地文件仓库可以保存和恢复笔记、目录树和仓库语法文件。
    用户可以创建、编辑、删除和移动笔记。
    用户可以创建、重命名、删除文件夹，并用文件夹组织笔记。
    用户可以编辑认知树原文，并用四空格缩进表达结构层级。
    当前笔记可以按仓库语法配置解析为结构树和诊断。
    仓库语法文件可以编辑，并影响仓库内所有笔记解析。
    用户可以在两篇笔记之间移动整棵块子树。
    块迁移界面必须让用户明确判断移动对象、子树范围和目标插入位置。

后移能力：

    搜索、导出、导入、链接、统计、同步、插件、桌面恢复和 AI 辅助整理。
    这些能力只有在笔记、语法和块迁移闭环稳定后再逐步扩展。


3. 当前主线

主线名称：

    语法编辑界面约束化

目标：

    用户通过受控表单编辑仓库语法配置。
    TOML 继续作为落盘格式，但不作为默认编辑入口。
    行首规则、行内规则、role、tone 和 kind 都由界面约束输入。
    语法配置不再区分 profile id 和版本号。
    语义 ID 作为内部机器标识保留，不作为普通编辑主字段。
    界面使用“仓库语法配置”这类功能名称，不直接展示 workspace.toml。
    tone 使用预设色块或 #RRGGBB 自定义颜色编辑。
    保存时由结构化 profile 生成 TOML，并复用现有保存 API。
    无效配置必须在保存前显示错误并阻止保存。

当前步骤：

    更新产品需求和工程架构文档。
    设计语法 profile draft 的纯函数。
    将 SyntaxWorkspacePanel 从 textarea 改为受控表单。
    将右侧详情调整为校验、生成摘要和保存反馈。
    验证通过后停下审核。

完成标准：

    用户无需手写 TOML 即可修改语法配置。
    用户可以新增、删除和编辑行首规则。
    用户可以新增、删除和编辑行内规则。
    用户可以通过预设色块或 #RRGGBB 自定义颜色编辑视觉提示。
    用户不需要理解或手动填写语义 ID。
    role、tone 和 inline rule kind 不能输入非法值。
    保存后的 TOML 可被现有 parser 和后端校验通过。
    语法无效时显示明确错误，不写入仓库语法文件。
