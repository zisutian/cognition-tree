2. 日常开发命令

安装依赖：

    pnpm install

浏览器前端开发模式：

    pnpm dev

Docker 后端服务：

    pnpm server

当前在 HTTP NoteRepository 接入前，前端开发服务器仅用于界面调试，不提供笔记文件保存。

单元测试：

    pnpm test

类型检查：

    pnpm check

前端生产构建：

    pnpm build


3. 提交前检查

提交前至少运行：

    pnpm test
    pnpm check
    pnpm build

后端脚本语法检查：

    node --check server/index.mjs
    node --check server/noteApiServer.mjs
    node --check server/noteFileStore.mjs

再检查空白问题：

    git diff --check

4.3 Web / Docker 数据

目标：

    将原文笔记保存到 Docker 后端管理的文件库，Windows 和 Linux 通过浏览器访问同一个服务实现互通。

已完成：

    建立前端 NoteWorkspace / NoteRecord / NoteTreeNode 模型。
    拆分 noteTree 领域操作，目录树变更不再混入笔记记录模型。
    建立 NoteRepository 接口。
    接入早期本地文件仓库，使用 workspace.json 保存仓库树和元信息，使用 notes/*.ctn 保存原文。
    支持目录树展示、选择笔记、新建笔记和编辑自动保存。
    支持通过右键菜单新建文件夹、重命名文件夹、删除文件夹和移动笔记。
    支持查看和更改当前仓库文件夹。
    支持仓库语法资源和笔记实际语法解析。

架构判断：

    仓库接近 Obsidian vault，是一个长期知识域。
    文件夹只负责组织、浏览、移动和新建落点。
    文件夹不绑定语法、不继承语法、不承载解析配置。
    仓库可以持有多套语法资源，后续需要提供简洁切换入口。
    笔记记录实际使用的 syntaxProfileId 和 syntaxVersion，并可以通过 syntaxImports 引用仓库内普通可见笔记中的语法块。
    跨笔记块移动是当前主线，块操作底座优先于仓库级语法切换入口。
    NoteRepository 是前端存储端口。
    桌面运行实现已从当前分支剔除，仅保留 NoteRepository 端口抽象。
    HttpNoteRepository 是当前主线实现。
    Docker 后端通过 HTTP API 提供 workspace 读取、保存、清空和仓库信息能力。
    Docker volume 保存 workspace.json 和 notes/*.ctn。

步骤：

    新增 Docker 后端最小服务。
