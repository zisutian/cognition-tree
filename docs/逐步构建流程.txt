3. 近期实施顺序

3.1 语法 profile 表达能力增强

目标：

    让语法文件可以声明可扩展 type、受控高亮 tone 和行内规则，同时保持解析底层结构稳定。

步骤：

    type 改为 ASCII kebab-case 机器语义 ID。
    marker rule 新增 role，只有 role = code 触发 fenced code block 行为。
    marker rule 和 inline rule 新增受控 tone。
    syntax profile 新增 inlineRules，支持 paired 和 single 两种行内规则。
    role、tone 和 inlineRules 必须显式写入语法文件，不保留旧 schema 兼容入口。
    前端 TypeScript 与后端 Node TOML parser 同步校验新 schema。
    编辑器高亮改为使用 tone class，不再依赖 type class。

小提交顺序：

    文档 schema 同步
    TypeScript 语法模型和默认 profile
    Node TOML parser 同步
    CTN 解析器 role / inlineRules 接入
    CodeMirror tone 高亮接入
    测试、自动验证和界面审核

3.2 拖拽式块迁移

目标：

    在显式迁移闭环稳定后，复用同一套移动 API 接入拖拽。

步骤：

    增加双笔记结构面板或结构树拖放入口。
    拖拽只负责选择源块和目标位置。
    迁移仍复用领域层移动 API。

3.3 Docker 打包与部署验证

目标：

    将已经稳定的 HTTP 后端容器化，并验证 Docker volume 持久化。

步骤：

    增加 Dockerfile。
    增加 compose 文件。
    明确 volume 数据目录。
    验证容器重启后数据保留。
