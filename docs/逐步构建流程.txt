2. 第一版闭环边界

第一版目标不是堆功能清单，而是先让核心认知树工作流闭合。

必须闭合：

    本地文件仓库可以保存和恢复笔记、目录树和仓库语法文件。
    用户可以创建、编辑、删除和移动笔记。
    用户可以创建、重命名、删除文件夹，并用文件夹组织笔记。
    用户可以编辑认知树原文，并用四空格缩进表达结构层级。
    当前笔记可以按仓库语法配置解析为结构树和诊断。
    仓库语法文件可以编辑，并影响仓库内所有笔记解析。
    用户可以在两篇笔记之间移动整棵块子树。
    块迁移界面必须让用户明确判断移动对象、子树范围和目标插入位置。

后移能力：

    搜索、导出、导入、链接、统计、同步、插件、桌面恢复和 AI 辅助整理。
    这些能力只有在笔记、语法和块迁移闭环稳定后再逐步扩展。


3. 当前主线

主线名称：

    持久化与解析边界收紧

目标：

    自动保存按顺序执行并合并等待中的旧快照。
    自动保存失败必须进入可见错误状态。
    WorkspaceRepository 不再把运行时 syntaxProfile 作为 workspace payload 发送。
    HTTP adapter 在响应进入 workspace 应用层前校验 DTO。
    File Store 使用原子文件替换，并串行执行写操作。
    引用图谱复用 CTN parser 的行内结构语义。
    块迁移界面只解析当前源笔记和目标笔记。

当前步骤：

    拆分 WorkspaceData 和前端运行时 NoteWorkspace。
    实现 HTTP DTO 校验。
    实现可合并的串行自动保存队列。
    实现 File Store 原子写入和写操作串行化。
    抽出 CTN 引用提取器。
    优化块迁移解析范围。
    补充自动保存、DTO、代码块引用和并发写入测试。
    验证通过后停下审核。

完成标准：

    快速连续更新不会让旧 workspace 覆盖新 workspace。
    保存错误不会产生未处理 Promise，并能显示在界面中。
    PUT /api/workspace payload 不包含 syntaxProfile。
    非法 workspace、syntax 和 repository info 响应在 storage adapter 被拒绝。
    note 和 manifest 文件通过原子替换写入。
    代码块中的 [[...]] 不进入引用图谱。
    迁移界面不再解析未选中的笔记。
