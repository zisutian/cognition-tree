2. 第一版闭环边界

第一版目标不是堆功能清单，而是先让核心认知树工作流闭合。

必须闭合：

    本地文件仓库可以保存和恢复笔记、目录树和仓库语法文件。
    用户可以创建、编辑、删除和移动笔记。
    用户可以创建、重命名、删除文件夹，并用文件夹组织笔记。
    用户可以编辑认知树原文，并用四空格缩进表达结构层级。
    当前笔记可以按仓库语法配置解析为结构树和诊断。
    仓库语法文件可以编辑，并影响仓库内所有笔记解析。
    用户可以在两篇笔记之间移动整棵块子树。
    块迁移界面必须让用户明确判断移动对象、子树范围和目标插入位置。

后移能力：

    搜索、导出、导入、链接、统计、同步、插件、桌面恢复和 AI 辅助整理。
    这些能力只有在笔记、语法和块迁移闭环稳定后再逐步扩展。


3. 当前主线

主线名称：

    仓库唯一语法模型收敛

目标：

    删除单篇笔记独立指定语法的模型。
    删除仓库内多语法文件管理。
    仓库只保留一份 syntax/workspace.toml。
    所有笔记统一使用 workspace.syntaxProfile 解析。
    语法界面只编辑当前仓库语法，不提供新增、删除和笔记级切换。
    块迁移发生在同一仓库语法环境内，不再做目标笔记语法兼容检查。

当前步骤：

    更新领域模型和 workspace 解析流程。
    更新前端语法编辑界面。
    更新 HTTP API 和文件仓库保存格式。
    更新测试和文档。
    验证通过后停下审核。

完成标准：

    NoteRecord 只保存笔记身份、标题、原文和时间。
    NoteWorkspace 只保存 syntaxProfile。
    workspace.json 不再保存默认语法字段或笔记语法字段。
    syntax/workspace.toml 是唯一语法配置文件。
    UI 不再出现语法文件列表、新建、删除和单篇笔记语法选择。
    旧多语法模型引用在 README、docs、src、server、tests 中清理干净。
