核心要求

版本：0.1
日期：2026-05-21


1. 产品定位

认知树不是 Markdown 编辑器，也不是传统富文本笔记软件。

目标是构建一个“可配置语法的认知树编辑器”，让用户直接记录概念、定义、条件、疑问、组分、自我理解、证据、例子和关系。

Markdown、HTML、PDF、纯文本只作为导出格式，不作为主要写作格式。


2. 核心原则

思维优先：

    编辑器优先服务思维链路，而不是服务文档排版。

缩进即作用域：

    缩进代表父子关系、展开关系、条件作用范围或局部语义范围。

符号即语义：

    行首符号、行内符号、块头符号映射为明确语义类型。

语法可配置，底层结构稳定：

    可配置符号、显示、导出方式。
    不随意配置行、缩进、父子块、块类型、转义、语法版本等底层结构。

本地优先：

    笔记优先保存在本地，用户拥有完整数据。

可导出：

    必须支持开放格式导出，避免数据囚笼。


3. 默认语法方向

默认行首符号：

    :        定义
    [?]      疑问
    [组分]   组分论述
    [分类]   分类论述
    [例子]   举例
    [条件]   条件说明
    [证据]   证据
    [反例]   反例
    [注]     注释
    [理解]   自我理解

缩进：

    缩进表示当前行属于上一层块。
    默认方向以 Tab 作为一个缩进单位。
    当前前端解析器同时兼容两个空格作为一个层级，方便早期测试。

行内符号方向：

    (...)    别名、英文、缩写、小解释
    [...]    小体量组分或举例
    <...>    局部概念引用
    [[...]]  全局概念引用
    \        并列
    *        可选
    !        否定或不支持
    @        所见即所得，不参与自动改写


4. 稳定数据模型

笔记至少包含：

    id
    title
    syntaxProfileId
    syntaxVersion
    createdAt
    updatedAt

块至少包含：

    id
    noteId
    parentId
    orderIndex
    type
    rawText
    parsedText
    props
    createdAt
    updatedAt

核心要求：

    每个块必须保留 rawText。
    解析器升级不能丢失用户原始输入。
    每条笔记必须记录 syntaxProfileId 和 syntaxVersion。


5. 第一阶段必须实现

编辑：

    创建笔记
    编辑缩进块
    Tab / Shift+Tab 调整层级
    支持定义、疑问、组分、自我理解、注释、条件

解析：

    按行切分
    计算缩进层级
    识别行首符号
    构建块树
    输出语义块模型
    输出诊断信息

视图：

    原文视图
    结构视图
    块类型识别
    缩进层级显示
    条件作用域提示

存储与导出：

    原文笔记保存为本地 .ctn 文件
    使用 JSON 保存仓库树和语法元信息
    支持纯文本导出
    支持 JSON 导出
    支持搜索标题和正文


6. 第一阶段暂不实现

    云同步
    多端同步
    AI 自动整理
    插件市场
    PDF 导出
    协作编辑
    复杂图谱


7. 技术路线

第一阶段技术栈：

    Tauri 2
    Vite
    React
    TypeScript
    CodeMirror 6
    TypeScript 自研解析器
    Rust
    本地文件库
    SQLite + JSON1 / FTS5 索引缓存
    Vitest
    Playwright
    pnpm

关键判断：

    CodeMirror 6 负责 .ctn 原文编辑、缩进、快捷键、语法装饰和结构视图联动。
    TypeScript 解析器服务前端装饰、结构视图和单元测试。
    Rust 负责 Tauri commands、本地文件读写和系统能力。
    文件库负责笔记原文、仓库树和语法配置元信息。
    SQLite / FTS5 作为后续索引缓存，不作为第一阶段必须依赖。


8. 成功标准

第一版成功标准：

    用户可以不用 Markdown 记录一条复杂概念笔记。
    用户可以通过缩进表达条件和层级。
    用户可以配置至少 5 种块符号。
    用户可以搜索定义、疑问、自我理解。
    用户可以导出纯文本和 JSON。
    旧数据不会因为语法配置变化而丢失。
