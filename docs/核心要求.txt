核心要求

版本：0.1
日期：2026-05-21


1. 产品定位

认知树不是 Markdown 编辑器，也不是传统富文本笔记软件。

目标是构建一个“可配置语法的认知树编辑器”，让用户直接记录概念、定义、组分、自我理解、代码片段、语法规则和关系。

Markdown、HTML、PDF、纯文本只作为导出格式，不作为主要写作格式。


2. 核心原则

思维优先：

    编辑器优先服务思维链路，而不是服务文档排版。

缩进即作用域：

    缩进代表父子关系、展开关系或局部语义范围。

符号即语义：

    行首符号、行内符号、块头符号映射为明确语义类型。

语法可配置，底层结构稳定：

    可配置符号、显示、导出方式。
    不随意配置行、缩进、父子块、块类型、转义、语法版本等底层结构。

语法块可导入：

    仓库可以持有语法资源，语法资源可以由普通可见笔记中的语法块提供。
    笔记可以通过引用语法块形成自己的有效语法。
    语法块引用实时生效，但不得改变缩进、父子块和 rawText 保留等底层结构。

本地优先：

    笔记优先保存在本地，用户拥有完整数据。

仓库即知识域：

    一个仓库对应一个长期知识方面，接近 Obsidian vault 的概念。
    仓库不是单篇笔记的位置，而是笔记、目录树、语法资源和索引缓存的边界。
    仓库切换应是显著但简洁的上下文切换。

目录只负责组织：

    目录和文件夹用于浏览、归类、移动和决定新建笔记落点。
    目录不绑定语法、不承载解析配置、不改变笔记行为。

可导出：

    必须支持开放格式导出，避免数据囚笼。


3. 默认语法方向

默认行首符号：

    :        定义
    >        自我理解
    -        组分、分类、例子或枚举项
    ```      代码块
    [语法]   语法规则

缩进：

    缩进表示当前行属于上一层块。
    默认方向以 Tab 作为一个缩进单位。
    编辑器中 Tab 插入四个空格，解析器按四个空格作为一个层级。

字体：

    UI 使用中文友好的系统黑体字体栈。
    .ctn 原文编辑区优先使用适合中文阅读的正文栈。
    语法 marker、路径、行号和代码化信息使用等宽字体。

行内符号方向：

    `...`    行内代码
    <...>    局部概念引用
    [[...]]  全局概念引用
    \        并列分隔


4. 稳定数据模型

笔记至少包含：

    id
    title
    syntaxProfileId
    syntaxVersion
    syntaxImports
    createdAt
    updatedAt

块至少包含：

    id
    noteId
    parentId
    orderIndex
    type
    rawText
    parsedText
    props
    createdAt
    updatedAt

核心要求：

    每个块必须保留 rawText。
    解析器升级不能丢失用户原始输入。
    每条笔记必须记录 syntaxProfileId 和 syntaxVersion。
    笔记可以记录 syntaxImports，用于引用仓库内普通可见笔记中的语法块。
    仓库可以保存多套 syntaxProfile，并提供简洁切换入口。
    文件夹不得保存 syntaxProfileId、syntaxVersion 或其他语法配置。
    跨笔记移动块时必须移动整棵子树，并检查目标笔记是否具备该子树所需语法；缺失时应提示并允许随迁语法块引用。


5. 第一阶段必须实现

编辑：

    创建笔记
    编辑缩进块
    Tab / Shift+Tab 调整层级
    支持定义、组分、自我理解、代码块和语法规则块

解析：

    按行切分
    计算缩进层级
    识别行首符号
    构建块树
    输出语义块模型
    输出诊断信息

视图：

    原文视图
    结构视图
    块类型识别
    缩进层级显示
    缩进作用域提示

存储与导出：

    原文笔记保存为 Docker 后端管理的 .ctn 文件
    使用 JSON 保存仓库树、仓库语法资源和笔记元信息
    支持纯文本导出
    支持 JSON 导出
    支持搜索标题和正文


6. 第一阶段暂不实现

    云同步
    多端同步
    AI 自动整理
    插件市场
    PDF 导出
    协作编辑
    复杂图谱


7. 技术路线

第一阶段技术栈：

    Vite
    React
    TypeScript
    CodeMirror 6
    TypeScript 自研解析器
    HTTP NoteRepository
    Docker 后端
    Docker volume 文件库
    SQLite + JSON1 / FTS5 索引缓存
    Vitest
    Playwright
    pnpm

关键判断：

    浏览器是当前主界面运行环境。
    Docker 后端负责笔记原文、仓库树、仓库级语法资源和笔记语法引用。
    Docker volume 保存 workspace.json 和 notes/*.ctn。
    NoteRepository 是前端存储端口，HTTP NoteRepository 是当前主线实现。
    CodeMirror 6 负责 .ctn 原文编辑、缩进、快捷键、语法装饰和结构视图联动。
    TypeScript 解析器服务前端装饰、结构视图和单元测试。
    目录树只表达组织结构，不参与语法解析。
    SQLite / FTS5 作为后续索引缓存，不作为第一阶段必须依赖。
    Tauri 桌面适配层暂缓保留，不作为当前主线继续扩展。


8. 成功标准

第一版成功标准：

    用户可以不用 Markdown 记录一条复杂概念笔记。
    用户可以通过缩进表达作用域和层级。
    用户可以配置至少 5 种块符号。
    用户可以搜索定义、组分、自我理解。
    用户可以导出纯文本和 JSON。
    旧数据不会因为语法配置变化而丢失。
